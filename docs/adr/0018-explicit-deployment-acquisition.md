# ADR 0018: 部署来源显式化，服务端不再替换用户选择

日期: 2026-09-07 · 状态: 已接受（取代 `plan-9-15-bug-02-model-source-reuse.md` 引入的「节点已有 > 默认源 > 模板声明」三级偏好与 `source_resolution`；其中跨源等价校验规则保留）

> 2026-10-16：部署显式选择获取方式（本地已有 / 节点间同步 / 公网下载 / 网络路径）由 [ADR 0048](0048-pull-settings.md) 取代：部署不再选来源，节点按拉取设置与同步组自行获取。保存模型的存储与权重来源仍由部署请求给出，并照本 ADR 校验不替换。

## 背景

模型从哪下、镜像从哪拉、节点上有没有，原本是三套互不知晓的隐式规则，部署页也不展示任何结果：

- 模型来源不是部署属性。直接部署读 `Model.Source`，模板部署另走一套三级偏好，之后还会替换用户传入的 `model_id`。选模板等于选来源，而全局 `default_model_source` 只在模板路径当平局判定，用户在设置页改了感觉不到。
- 镜像 mirror 链只对镜像目录内已登记的 ref 生效，模板 spec 的镜像多半不在目录里，候选退化成 canonical 一条。
- 缓存有两套判定，部署流程一套都不读：向导、节点自动选择和调度器磁盘估算都不看镜像缓存；模型侧见到 `acquisition=download` 就直接放弃节点间同步，即使别的在线节点已有完整副本，也直连公网，超时即失败不再重试。

叠加的结果是：用户看不到会发生什么，也改不了；线上部署失败率高的那条路径，恰好是本可以从同集群另一台节点秒级拷贝的模型。

## 决策

**获取来源是部署请求的显式字段。** 请求携带 `model_source` 与 `image_pull`；两者都使用 `local_present` / `peer_sync` / `public`，公网时含 provider 与 network 路径。取值全部来自 evaluate 返回的候选集合，客户端不自行拼字符串。

**服务端只校验，不替换。** 候选失效时返回 `ACQUISITION_CANDIDATE_STALE` 要求重新评估，而不是静默改用另一个来源。显式选定的 peer 源节点是唯一候选；它离线或副本不再完整时直接失败，不会换成另一台节点或公网下载。模板与目录元数据只做预填。

**删除 `default_model_source`。** 设置、种子、模板路径的偏好排序一并删除，`PUT /settings/default_model_source` 返回 410。

**`model_endpoint` 并入网络重写规则。** 模型下载 URL 与镜像拉取候选此后共用一套 `network.rewrites` 表达，迁移把非空 endpoint 转成一条 `https://huggingface.co → <endpoint>` 规则。单次部署选择的网络路径写入该下载任务，不改动节点全局配置。

## 取舍

放弃了「系统自动挑一个能用的来源」这份便利：请求不带 `model_source` 时服务端仍按推荐值填充并在快照标记，但用户一旦选定，服务端不再在其背后改判——包括那些改判本来是对的场景（例如所选 peer 恰好离线，而另一台在线节点有完整副本）。换来的是可解释性：部署详情能回答「这次的权重从哪来、镜像从哪拉」，失败时用户能看到是哪条路径失败而不是静默卡住。

`default_model_source` 的删除不可逆：依赖该设置做集群级来源偏好的运维，此后需要在每次部署时显式选择，或用网络重写规则把公网地址指向内部镜像。

2026-09-08 补充：空 revision 在来源选择入口解析一次，按 provider、repo、subfolder 查找已有 identity，优先目标节点已就位的行，再按 ID 确定顺序；没有匹配时才创建空 revision 行。精确匹配与跨源等价函数不引入通配语义。新目录条目允许省略 revision，既有条目的 revision 保留：批量删除会降低复现能力，且公网兜底可能让不同节点在同一 model ID 下取得不同上游版本；未来若要删除，须先设计多机版本收敛机制。

2026-10-27 补充：显式 provider 也复用同一 provider、同一 repo 下 revision 为空、目标节点已能使用、且体积与 spec `weight_bytes` 相差不超过 0.1%（至少 1 MiB）的副本。这类条目多来自共享存储扫描导入（例如 provider CLI 下载的目录，没有 commit 信息），空 revision 表示未知而非另一版本；不复用时会在同一存储上按 `<repo>-<revision>` 再下载一份完整权重。该复用不跨 provider，也不复用 revision 已知且不同的条目；部署快照记录实际挂载的条目。

来源候选保留 spec 声明的完整列表，本地副本只影响默认建议。显式公网 provider 约束实际下载 identity，避免跨源等价复用把请求转到另一个 provider。镜像目录查询先精确匹配，再查声明的 registry_sources；缓存查询独立按 ref 询问节点，失败原因通过 cache_reason 暴露。

- 新包 `internal/server/acquisition` 只产候选、不做选择，输入是显式 facts 结构体。
- 新包 `internal/server/imagecatalog/pullref` 收敛拉取候选顺序，store 与 imagecatalog 共用一份实现；原 `store.imagePullRefsForImage` 这份分歧实现删除。ADR 0017 背景中提到的两处候选链实现，此后是同一份代码。
- 拉取候选对任意 tagged ref 生效，不再要求 ref 已登记在镜像目录中；前缀匹配按 Docker Hub 归一化后的段边界进行。
- 节点网络覆盖有了读写 API 与节点详情页卡片，evaluate 的「本节点覆盖」标签因此有确定来源。
