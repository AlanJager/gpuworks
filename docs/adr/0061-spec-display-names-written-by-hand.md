# ADR 0061: 推理档位的显示名由人写在目录里，不再由前端拼出

日期：2026-11-02 · 状态：已接受（修改 0009 的「UI 从谓词现算标签」）

## 背景

推理模板详情页的档位名曾由前端拼成「{芯片对象} {通用|兼容|优化}档位」：芯片对象来自 spec 的 `gpus.display_target`（缺失时前端用正则从型号里猜），档位类型来自 `display_profile`。两个字段都在 YAML 里手写，和 `gpus` 的真实匹配条件没有约束关系。内置目录里有 194 组同一模型、同一引擎下显示名相同的档位（122 个模型），其中 149 组连量化、场景标签也相同，用户必须点开才知道区别；还有标成「NVIDIA」实际只匹配 Hopper 或 Blackwell 的档位。「通用 / 兼容 / 优化」从未定义，用法自相矛盾。

真正区分兄弟档位的是芯片代际、量化与权重发布方、显存门槛、固定卡数、投机解码 / Engram 卸载 / 多机等形态、镜像版本。哪几项值得写进名字因档位而异。

## 决策

1. 删除 spec 级 `display_profile` 与 `gpus.display_target`；导入时仍读这两个键以兼容旧模板，但忽略并给出 `CATALOG_DISPLAY_PROFILE_RETIRED` 警告，不存储、不再导出。
2. spec 新增人写的 `display_name_zh_cn`、`display_name_en`，各存一列，server 原样下发，前端按语言选一个、缺一种时用另一种、都没有时显示 spec 的 `name`，不再推导任何名字。
3. 名字格式为「适用卡 · 量化 [· 关键门槛或形态]」，写法见[推理目录规范 · 显示名](../reference/inference-catalog-spec.md#显示名)。目录校验同一模型、同一引擎内中英文名各自唯一、单行、限长；内置档位两个名字都必须写（seed 测试守护）。
4. 详情抽屉的「适用 GPU」显示 `gpus` 的真实匹配条件，名字只是摘要。

## 取舍

- **人写 vs 按字段自动生成**：自动生成只能拼固定几个维度，要么名字太长，要么漏掉真正的区别（例如两个档位只差上下文长度）。人写的代价是新增档位时要多写两行，并可能写得与匹配条件不一致；唯一性校验能拦住重名，不一致靠评审与名字里的芯片名对照。
- **两列 vs 一个按语言的映射**：只有中英两种界面语言，与模型级 `readme_zh_cn` / `readme_en` 同形，带类型的列比 JSON 映射简单，也符合 [ADR 0032](0032-typed-columns-json-as-opaque-snapshot.md)。

## 后果

- 存量用户档位没有名字，显示 spec `name`，编辑时补上即可。内置档位随目录升级写入名字。
- ADR 0009 中「具名类的中文展示名消失，UI 需从谓词现算标签」不再成立：展示名回到目录数据里，但写在每个 spec 上，而不是一个具名芯片类上。
