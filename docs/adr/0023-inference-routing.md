# ADR 0023: 多副本推理网关默认使用负载均衡并重试连接级失败

日期：2026-09-23 · 状态：已接受

同一部署的多个运行中副本默认使用 least-request 选择。候选实例和节点身份由服务端内存快照维护，选路不在请求热路径查询数据库；本机在途请求数是主信号，新鲜的引擎排队数与 KV 使用率只作为软惩罚。节点隧道或目标端口在收到上游响应前失败时，网关在候选副本间重放请求，单个实例按失败次数短暂冷却；一旦拿到上游响应（包括 5xx）就原样返回，不再重试。

请求 body 先进入有全局预算的内存 replay body，超过阈值再落盘，并通过 `GetBody` 为每次重试创建独立 reader。部署可以选择 `least_request`、确定性 rendezvous 的 `prefix_affinity` 或保留旧语义的 `failover`；策略属于路由配置，不属于引擎启动参数，因此修改策略不会重启实例。

本决策不实现跨 server 的负载共享、精确 KV 事件感知、睡眠排空或 P/D 分离。候选快照的定时刷新、事件触发和未命中慢路径为未来 HA 保留最终一致性；亲和哈希使用跨进程稳定的 FNV，而不是进程随机种子哈希。
