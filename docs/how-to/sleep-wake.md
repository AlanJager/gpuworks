# 操作 sleep / wake

**适用场景**：一张卡要在多个模型间轮流使用，想让暂时不用的实例释放显存但保留容器，需要时再唤醒。

**前置条件**：

- 实例是单机 vLLM 部署，并在创建时打开了“可休眠”；SGLang 和多机分布式部署不支持，见[限制](#限制)。
- L1 休眠要求主机内存容纳与权重等量的数据，内存不够时用 L2。
- 想在同一张卡上放两个模型，见[一张 GPU 跑两个模型](../tutorials/one-gpu-two-models.md)。

实例开启可休眠后，在部署详情点击"休眠"即可通过 vLLM 的 sleep mode 释放显存；
容器本身继续运行，实例状态仍是 `running`，只是 `sleep_level` 从 0 变为 1 或 2。
此时网关对该模型返回 HTTP 503，并带"model is asleep; wake it first"提示，不会把
请求转发到已休眠的引擎（休眠指令一发出就停止转发，不等 agent 回报，否则新请求会被
vLLM 排队、睡着后挂死）。

## 只睡一部分：副本与 PD 角色

多副本的部署可以只让其中一些副本休眠，其余副本照常服务：

- **单个副本**：在该副本 leader 的实例面板点"休眠副本（L1）"/"唤醒副本"，对应
  `POST /api/v1/instances/{uuid}/sleep?level=&mode=` 与 `POST /api/v1/instances/{uuid}/wake`。
  只有一个副本的部署不显示这两个按钮，用部署级的即可。多机副本按整个副本睡和醒：指令发给 leader，
  vLLM 的多机执行器带着 follower 一起释放显存、唤醒时一起重载权重，follower 自己不接收指令。
  follower 不上报睡眠级别，调度账本按它所在那一代 leader 的上报级别算：leader 睡着时 follower 的卡也只计残留，
  唤醒时 follower 的卡同样要放得回去；"唤醒放得下的副本"按整个副本判断，一个 rank 放不回就整个副本保持休眠。
- **PD 的一个角色**：部署详情里"休眠 Prefill（L1）"，对应 `POST /api/v1/deployments/{id}/sleep?role=prefill`。
  只提供 PD 模式允许为空的角色（vLLM NIXL 下是 prefill）；prefill 全部休眠时 decode 自己完成 prefill，
  与 prefill 缩到 0 相同，不计降级。decode 只能随整个部署一起休眠，最后一个醒着的 decode 实例也不能单独休眠
  （`SLEEP_ROLE_CANNOT_EMPTY`）。

睡眠意图记在每个实例上：网关只把请求转给没有被下令休眠、也没有在休眠的实例，一个都不剩时才返回
503 asleep。部署详情的睡眠标签按副本计：全部休眠显示级别，部分休眠显示"部分休眠 · k/N 个副本"。

部署级的"休眠"让部署整体处于睡眠命令下，这期间新起的实例（比如失败后重建）也按该级别启动；
只睡一个副本或一个角色不算，那个副本被重建时新实例是醒着的。唤醒任何一个副本都会撤销部署整体的睡眠命令，
其余已休眠的副本保持休眠。

一个实例休眠失败时，只回退它自己的意图（以及仍在生效的部署整体命令），已经睡着的其他副本不会被一起唤醒。

## 两种级别

| 级别 | 权重去向 | KV cache | 唤醒方式 | 适用 |
|---|---|---|---|---|
| L1（快速） | 挪到主机内存，占用与权重等量的 RAM | 丢弃 | 一步，秒级 | 主机内存够用 |
| L2（深度） | **直接丢弃，不落盘** | 丢弃 | 四步：恢复权重缓冲 → 从模型目录重新加载 → 恢复 KV cache → 清理前缀缓存；十几秒到几分钟 | 主机内存不够 |

L2 没有"占用哪个磁盘"的配置项：唤醒时读的是部署本来就挂载的模型目录。

KV cache 保存请求历史 token 的 Key/Value，休眠时其中的内容会被丢弃；唤醒时重新分配的是空的 KV cache 空间，不会恢复旧请求状态。前缀缓存建立在 KV cache block 上，用于复用已经计算过的公共前缀。L2 重新加载权重后，旧前缀缓存可能对应已经释放的权重，因此唤醒最后还会调用 `reset_prefix_cache` 清理复用记录。L1 的权重内容仍保存在主机内存中，直接唤醒即可，不需要这一步。

## 休眠时在途请求怎么办

点击休眠会弹框选择方式：

- **等待完成**（默认）：引擎先跑完正在处理的请求，期间新请求被网关拒绝（503），跑完再睡。
  一次很长的生成会相应推迟休眠；agent 侧单次指令上限 10 分钟。
- **立即中止**：正在处理的请求立刻收到错误。

API 上对应 `POST /api/v1/deployments/{id}/sleep?level=1|2&mode=wait|abort`。

## 休眠后这张卡能做什么

休眠实例在调度账本里只占约 1.5 GiB 残留（CUDA context 等），其余显存可以给新部署。
部署表单评估时若放不下，会给出"休眠某某可释放约 N GiB"的建议，点"休眠并重新评估"
即可完成休眠并自动重新评估。评估文案里"可用显存"已扣掉残留，并注明来源。

## 唤醒

点击"唤醒"或调用 `POST /api/v1/deployments/{id}/wake`。服务端先检查这张卡当前能否
放回休眠实例的显存：如果卡已被新部署占用，返回 409 `WAKE_INSUFFICIENT_GPU_MEMORY`，
参数里有卡号、缺口 GiB 和占用者名称；先停止或休眠占用者再唤醒。部署级唤醒默认全有或全无；
有多个休眠副本时，被拒绝后界面会提供"唤醒放得下的副本"（`?partial=true`），只唤醒放得回原卡的那些，
响应里列出其余副本的差额。通过后等待
`sleep_level` 回到 0 即可再重试 `/v1` 请求（过程中实例状态始终是 `running`）。唤醒处理中
的实例按完整显存 claim 计入调度，因此同一张卡不会在 agent 上报醒来前被再次分配。

agent 侧唤醒或休眠失败时，会先通过 `/is_sleeping` 探测。L2 唤醒在权重、KV cache 或前缀缓存步骤之后失败时无法从布尔探针推断显存占用，实例会标记失败、保留完整显存 claim，并禁止网关转发；controller 会移除并重建这一代实例，恢复到已知状态。可确认的失败会保留实际级别、失败目标和原因，server 仅当该实例的期望仍是这次失败目标时回退它的期望级别：唤醒失败回到休眠，休眠失败回到醒着。失败不会后台自动重试，处理问题后再次点击对应按钮即可发出新指令。状态阶段为 `sleep` 的上报会进入普通实例状态时间线事件，UI 从时间线读取失败原因。

## 限制

- 只支持 vLLM；SGLang 不能休眠（创建时就会拒绝声明可休眠）。
- PD 部署的 KV 走主机 RDMA 网络时不能声明可休眠（`PD_SLEEP_RDMA_UNSUPPORTED`）：NIXL 把 KV cache 显存注册给 RDMA 网卡，
  引擎休眠释放这块显存后唤醒时申请不回来（实测报 CUDA out of memory）。KV 走以太网的 PD 部署、经 RDMA 走集合通信的普通多机部署都可以休眠。
- 自定义镜像不做探测：以引擎能力声明为准，镜像缺 sleep 端点时休眠会在实例事件里报错。
- 引擎的 sleep 端点由 `VLLM_SERVER_DEV_MODE=1` 打开，前提是引擎只监听本机、经 agent 隧道
  访问；部署形态改变时要重新审视这一点。
- 停止实例与 sleep 不同：stop 会真正停止并删除运行容器，需在部署详情里点"启动"（`POST /api/v1/deployments/{id}/start`）才能恢复。
