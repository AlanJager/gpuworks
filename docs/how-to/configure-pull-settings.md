# 配置镜像与模型拉取：来源规则、代理、同步组与凭据

**适用场景**：节点拉镜像或下模型慢、拉不到；要让内网节点走自建 Harbor 或内网 Hugging Face 代理；节点要经代理出网；私有仓库或 gated 模型需要登录；多机房或租用的云主机之间不该互相复制；完全离线的集群；docker 节点改了代理不生效。

部署不再选择镜像或模型从哪里来。每台节点启动副本时自己决定（[ADR 0048](../adr/0048-pull-settings.md)、[ADR 0050](../adr/0050-model-pull-sources-and-proxies.md)）：

1. 本地已有，直接用；
2. 同一同步组里有在线节点持有，就从它复制；
3. 否则按候选依次拉取：镜像的候选来自镜像的等价副本与适用于这台节点的来源规则；模型的候选来自适用的站点规则与模型登记的站点本身。

扩副本、重启、迁移、多机部署和镜像页、模型页的「拉取到节点」都走同一套判断。配置入口都在设置 → 拉取设置，分「来源规则」「代理」「同步组」「凭据」几页。

## 不配置时会怎样

- 镜像目录里的官方镜像同时发布在 Docker Hub、quay.io 与华为云 SWR。节点并行探测这几个仓库的 `https://<host>/v2/`（5 秒超时，结果缓存 30 分钟，走与拉取相同的代理），先试能连上且延迟最低的。
- 模板声明的 `image_sources` 是同一镜像的其他副本，排在目录副本之前，同样由节点排序。
- 下载阶段 3 分钟没有新增字节视为卡住，换下一个候选；失败或卡住的仓库在这台节点上 30 分钟内排到最后。慢但还在下载的不会中途换。层下载完、运行时解包（进度显示「解包镜像层」）期间不判卡住；一个候选从开始拉取到解包完最多 60 分钟。
- 模型默认从登记的站点（Hugging Face 或 ModelScope）下载，节点直连，不设代理（节点自己的环境变量 `HTTP_PROXY` 等仍然有效）。目录 URL 来源的模型只从它自己的目录下载。
- 预置一个不限节点的同步组 `default-all-nodes`：节点之间会自动复制镜像和模型。两台节点连不通（例如两台云容器各自在 NAT 后面）时，复制在约 10 秒内失败，这一对节点 3 小时内不再尝试，副本改为自己拉取。

探测只判断「能不能连上」，不判断「下得快不快」：Docker Hub 与 quay 的数据由 CDN 下发，`/v2/` 秒回不代表数据能下动，卡住判定兜底。docker 只在终端上输出逐层字节进度，所以 agent 在伪终端里运行 `docker pull`；节点分配不了伪终端时退回管道，没有字节进度，卡住判定对它不生效，只受单个候选 60 分钟的上限约束。nerdctl（以及经 nerdctl 拉取的 Kubernetes 节点）每 100 毫秒重画一张进度表，agent 把它换算成逐层字节进度；所有层下载完、表格只剩耗时在走时即为解包。nerdctl 只显示一位小数，超过 1 GiB 的层已下载量每 0.1 GiB 才变一次，所以这样的层还没下完时，卡住时限放宽到按 100 KiB/s 走完一步所需的时间（约 17.5 分钟）；比这更慢的下载不判卡住，只受单个候选的上限约束。udocker 不输出字节，agent 按镜像清单逐层读取层文件的大小作为进度。

运行时升级后进度输出的格式可能改变。agent 读到不认识的进度格式（nerdctl 进度表里新的状态词或字节写法、docker 新的层状态）时，这次拉取不再判卡住，只受单个候选的上限约束，不会因为读不懂而误判换源。拉取消息里会出现 `Progress output not understood, stall check off: …`，agent 日志里有一条带原始行的警告，便于更新解析。

## 来源规则

设置 → 拉取设置 → 来源规则，同一张表同时覆盖镜像和模型站点，由「匹配」是否以 `http://` 或 `https://` 开头区分：不带协议的是**镜像规则**，带协议的是**站点规则**（模型站点）。

### 镜像规则

每条规则：

| 字段 | 含义 |
|---|---|
| 匹配 | 仓库 host（`docker.io`、`ghcr.io`、`registry.example:5000`）覆盖该仓库的所有镜像；引用前缀（`gpuworks/`、`quay.io/team/app`）覆盖前缀下的镜像 |
| 替代地址 | 有序列表。host 规则保留仓库路径：`docker.io` → `harbor.corp.example/dockerhub-proxy` 把 `nginx:1` 变成 `harbor.corp.example/dockerhub-proxy/library/nginx:1`；前缀规则替换前缀 |
| 允许回源 | 替代地址都失败后，是否还试镜像原来的仓库。纯内网关掉 |
| 适用节点 | 节点标签选择器，空为全部节点；租用的云主机自带 `gpuworks.ai/provider`、`gpuworks.ai/region` |

规则按列表顺序生效：适用于节点的规则产生的替代地址排在最前，然后才是镜像自己的副本（由节点探测排序）。没有替代地址、又关闭回源的规则表示「不许从这个仓库拉」；一台节点对某个镜像什么候选都不剩时，启动失败并写明原因。

规则按列表顺序生效，适用于节点的所有匹配规则叠加（见下文站点规则的叠加说明，镜像规则同理）。规则在 agent 里以「拉另一个地址」实现，拉到后在本地 tag 回原名，不改 `daemon.json` 或 containerd 的 `hosts.toml`。所以规则只对平台发起的拉取生效，在节点上手动 `docker pull` 不走规则。

### 常见写法

| 场景 | 规则 |
|---|---|
| 内网节点只能走自建 Harbor 代理缓存 | `docker.io` → `harbor.corp.example/dockerhub-proxy`、`quay.io` → `harbor.corp.example/quay-proxy`，关闭回源，适用 `site=idc-a`；Harbor 需要登录时配凭据 |
| 公司内部也推了一份官方镜像 | `gpuworks/` → `registry.corp.example/gpuworks/`，允许回源 |
| 某个模板的镜像只在 ghcr | `ghcr.io` → 可用的 ghcr 镜像站，允许回源；或者让模板作者写 `image_sources` |
| 想用社区 Docker Hub 加速器 | `docker.io` → 加速器地址，允许回源。社区加速器没有 SLA，可能有白名单或限速（如 DaoCloud 大陆约 1 MB/s），平台不内置任何加速器 |

### 站点规则（模型）

匹配写站点根，不带路径，例如 `https://huggingface.co`、`https://modelscope.cn`。字段：

| 字段 | 含义 |
|---|---|
| 匹配 | 站点根 `https://huggingface.co`；协议和主机名必填，不能带路径 |
| 替代地址 | 有序列表，`http(s)://` 地址，可以带路径，例如 `https://hf-mirror.com`、`https://xget.example/hf`、`http://hf-proxy.corp:8090`。节点把原来对该站点的请求改发到这个地址上 |
| 允许回源 | 替代地址都失败后，是否还连站点本身。纯内网关掉 |
| 适用节点 | 节点标签选择器，空为全部节点 |
| 用于管理节点获取模型元数据 | 勾选后，管理节点（server 所在机器）读模型元数据时可以用这条规则的地址；只有站点规则有这个勾选 |

**规则会叠加**：一台节点下载某个站点的模型时，所有匹配的规则按列表顺序把各自的替代地址依次排进候选，去重，最后才是站点本身。任何一条匹配的规则关闭了回源，站点本身就不在候选里。什么都不剩时，下载被禁止（`WEIGHTS_FETCH_FORBIDDEN`）。

目录 URL 来源的模型（登记时给的是 HTTP 目录地址）只从它自己的目录下载，规则不作用于它们。ModelScope 与 Hugging Face 互不回退：模型登记在哪个站点，就只在那个站点的规则和站点本身里找。

#### 节点怎样依次尝试

服务器按节点算好候选（规则的替代地址在前，站点本身在后），agent 逐个尝试：

- 一个地址出现连接、DNS、TLS 错误，或任何 HTTP 错误状态（包括镜像站没有这个仓库返回的 404、401/403），这个地址冷却 30 分钟，立即换下一个。冷却中的地址下次排在最后，不会被剔除；冷却与镜像拉取共用。
- 单个连接连续 5 分钟收不到数据算一次卡住；同一地址连续卡住 2 次换下一个。
- 瞬时错误在后面还有候选的地址上最多重试 6 次；最后一个地址保留 16 次，并且在最后一个地址上卡住只是重试，不再换。
- 仓库版本是固定的 commit 时，换到下一个地址会接着已下载的部分续传；否则（版本是 `main` 之类的分支）文件从头开始。

进度写「正在从 <host> 下载」，切换后写「正在从 <host> 下载（已切换：<原 host> …原因）」。模型页显示当前站点，鼠标悬停显示切换原因。

#### 管理节点怎样读元数据

登记模型、刷新元数据、模板与目录 URL 登记时，管理节点要读仓库记录或 `config.json`。它用**勾选了「用于管理节点获取模型元数据」**的站点规则的地址，逐个候选询问（每个 5 秒），从第一个能答的地址读完全部内容；站点本身只在这些规则允许回源时才作最后候选。

管理节点读不到时，登记仍然成功，只是没有元数据，响应里带 `metadata_notice`：`MODEL_METADATA_UNREACHABLE`（写明试过哪些地址）或 `MODEL_METADATA_FORBIDDEN`（规则禁止）。控制台把它展示出来，并指向这个勾选。部署准入对每个模型只读一次，管理节点连不上仓库不会让部署被拒绝。

控制台里登记或刷新 Hugging Face 模型时，浏览器先从 `GET /api/v1/pull/metadata-sources?source=huggingface`（管理节点的候选地址）读元数据，不再写死 hf-mirror.com；只有浏览器真的读到了内容才标记为浏览器读取，否则由 server 读。

server 的 `--model-endpoint` 启动参数仅供进程内测试夹具使用，效果等同于 Hugging Face 与 ModelScope 各一条规则，替代地址指向该端点、不回源、勾选「用于管理节点获取模型元数据」，不是给生产使用的入口。

## 常见网络配置示例

下面是各种网络环境下的填法。所有地址都要自己填，平台不内置任何镜像站、加速器或预设。

| 场景 | 配置 | 结果 |
|---|---|---|
| A. 海外或节点能直连公网 | 不配置 | 直连 huggingface.co / modelscope.cn、Docker Hub |
| B. 大陆，用公网镜像站 | 站点规则：匹配 `https://huggingface.co`，替代地址 `https://hf-mirror.com`，允许回源 | 先走 hf-mirror，失败或同一地址卡住 2 次回 huggingface.co |
| C. 机房有内网 HF 代理 | 站点规则：匹配 `https://huggingface.co`，替代地址 `http://hf-proxy.corp:8090`（可再加 `https://hf-mirror.com`）；只准走内网就关闭「允许回源」。镜像同理：`docker.io` → `harbor.corp.example/dockerhub-proxy`，关闭回源 | 依次尝试；关闭回源后 huggingface.co 不在候选里 |
| D. 海外租机加大陆机房 | 把 B 或 C 的规则「适用节点」限定为 `site=idc-sh` 或 `gpuworks.ai/region` 等标签 | 海外节点直连，大陆节点走镜像；租用的云主机自带 `gpuworks.ai/provider`、`gpuworks.ai/region` |
| E. 完全离线 | 共享存储预置模型，或规则指向内网镜像并关闭回源（见 I） | 不碰公网；所有候选被禁止时部署页报 `WEIGHTS_FETCH_FORBIDDEN` |
| F. gated 或私有模型 | 「凭据」里添加 `huggingface.co` + token | 只在 https 连 huggingface.co（及其 CDN 子域）时带 token，镜像站与其他域名都不带 |
| G. 管理节点与计算节点网络不同 | 给管理节点能用的那条站点规则勾选「用于管理节点获取模型元数据」，那条代理勾选「用于管理节点出站访问」 | 管理节点读元数据、取 logo、登记目录 URL、预览镜像归档、测试登录都只用勾选的规则与代理；连不上时提示指向这个勾选 |
| H. 节点要经代理出网 | 「代理」页新增一条，按标签限定（如 `site=idc-sh`），填 `http_proxy` / `https_proxy` / `no_proxy`；管理节点也要走就勾选「用于管理节点出站访问」 | 匹配的节点拉镜像、下模型、探测都走它；docker 节点同时写 dockerd 代理并提示是否生效 |
| I. 离线导入 | 把模型目录拷到某节点或共享存储，登记为本地路径，或先登记 HF / ModelScope 模型再在该节点「登记路径」；整个集群离线时再加两条「禁止」站点规则 | 元数据从本地文件读，其他同组节点从它复制，不碰公网 |

### hf-mirror.com 的说明

hf-mirror.com 是个人运营的公共镜像站，没有 SLA，可能限速、改版或下线，所以平台不把它写成默认值。上面的 B 场景需要你手动填。生产环境建议自建代理（如 xget）或 Harbor、Nexus 一类的内网缓存，把它放在替代地址的第一位，hf-mirror 与站点本身当后备。

### 完全离线：两条「禁止」规则

没有出口的集群里，没有候选的下载要等公网连接超时才失败。加两条站点规则让平台立即知道公网不可用：

| 匹配 | 替代地址 | 允许回源 | 适用节点 | 用于管理节点获取模型元数据 |
|---|---|---|---|---|
| `https://huggingface.co` | 空 | 关 | 空（全部） | 勾选 |
| `https://modelscope.cn` | 空 | 关 | 空（全部） | 勾选 |

之后需要的模型只能来自：节点上已有的目录、挂载的共享存储、同组节点复制。缺少来源时部署页直接说明，而不是等待下载超时。内网有镜像站时，把它填进替代地址，其余不变。

### 离线导入模型

1. 把模型目录拷到某台节点（或共享存储）。
2. 两种登记方式任选：登记成本地路径（来源 local）；或先登记 Hugging Face / ModelScope 模型（让部署模板按来源找到它），再在模型页对那台节点「登记路径」。
3. 「登记路径」会用本地目录补齐模型缺失的元数据（config、README、大小），已有的不覆盖；如果目录是 `huggingface-cli download --local-dir` 下载的，`.cache/huggingface/download/*.metadata` 全部指向同一个 commit，且这是该模型唯一的一份副本，模型会固定到这个 commit。
4. 其他同步组内的节点会从有这个模型的节点复制。

## 测试连通

站点规则抽屉里有「测试连通」，在保存前就能验证：选 1 到 5 台节点和一个仓库（默认 `Qwen/Qwen3-0.6B`），每台节点按它下载时的方式（它自己的代理、`no_proxy`、凭据）探测草稿规则的每一个地址：

- Hugging Face 风格地址：`GET <地址>/api/models/<仓库>/revision/main`，应答后再取 `<地址>/<仓库>/resolve/main/config.json` 的第一个字节。门禁仓库的仓库信息对所有人公开、只拒绝下载文件，所以要测门禁模型时把仓库改成它，文件被拒（401/403）就显示「需要凭据」；仓库里没有 config.json（如 GGUF 仓库）不影响结论；
- modelscope.cn：`GET <地址>/api/v1/models/<仓库>`；
- 每个地址 10 秒超时。

结果按节点和地址列出：可用、需要凭据（401/403：到「凭据」里给这个站点配令牌，地址本身是通的）、HTTP 状态码、不可达（附延迟）。接口 `POST /api/v1/pull/source-rules/test`。

## 同步组

设置 → 拉取设置 → 同步组。节点只自动从同组节点复制镜像和模型：

- 一个节点属于多个组时，可以从任何一个同组节点复制；两节点共享多个组时取最严的限速。
- 不属于任何组的节点不自动复制，只能在模型页或镜像页手动发起。
- 同步组表达「连得上但不该走」：两个机房之间是慢专线、两台带公网 IP 的机器在不同大洲。连不通的情况不需要分组，复制会快速失败并回退。
- 它是普通的组，可以改名、收窄或删除。多机房集群可以删掉它，按机房标签各建一个组；租用的云主机可以用 `gpuworks.ai/provider` 或 `gpuworks.ai/region` 分组。要恢复全部节点互相复制，新建一个不填节点条件的组即可。
- 同一标签选多个值时满足其一即可，不同标签需同时满足。要单独选中某几台节点（例如没有云厂商标签的自有机器），先在计算节点页给它们加一个标签。
- 每个组可以设复制限速，默认不限。

复制用的网络仍按[存储同步网络](configure-networks.md)选择：同一存储同步网络上的节点优先作为源。

## 凭据

设置 → 拉取设置 → 凭据。每个 host 一条，分两种，加密存储，接口与页面都不回显：

| 种类 | 填写 | 怎么用 |
|---|---|---|
| 镜像仓库 | 仓库 host、用户名、密码或令牌 | 随节点期望状态下发，agent 只放在内存里。拉取时写一个临时 `DOCKER_CONFIG` 目录，拉完删除，不执行 `docker login`，不碰节点上的 `~/.docker/config.json` |
| 模型站点 | 站点 host（如 `huggingface.co`）、token，用户名留空 | 以 `Authorization: Bearer` 发送，**只在 https 且 host 完全一致时**带上：镜像站和其他域名永远拿不到。遇到重定向时，同域名及其子域名（例如站点的 CDN）会带，其他域名不带 |

- udocker 的原生拉取直接带认证；udocker 命令行回退路径不支持认证，按匿名拉取。
- 「测试登录」从管理节点发起，经「用于管理节点出站访问」的代理：镜像仓库请求 `/v2/`，token 请求 Hugging Face 的 `GET /api/whoami-v2`。节点能到而管理节点到不了的站点会测试失败，以实际拉取为准。
- 目前只确认了 Hugging Face 的私有与 gated 仓库，ModelScope 私有仓库尚未验证。
- 接口 `/api/v1/pull/credentials`；旧的 `/api/v1/pull/registry-credentials*` 返回 410。

## 代理

设置 → 拉取设置 → 代理。有序的条目列表，每条：

| 字段 | 含义 |
|---|---|
| `http_proxy`、`https_proxy` | 代理地址 |
| `no_proxy` | 不走代理的目标，语义同 Go 的 `NO_PROXY`：`*` 表示全部；可写 IP、CIDR；域名匹配自身及其子域名；以 `.` 或 `*.` 开头只匹配子域名；可带端口；loopback 与 localhost 永远不走代理 |
| 用户名、密码 | 密码加密存储，不回显 |
| 适用节点 | 节点标签选择器，空为全部节点 |
| 备注 | 自由文字 |
| 用于管理节点出站访问 | 勾选后，管理节点的出站访问使用这条 |

一台节点用**第一条**满足适用条件的条目，条目之间不叠加；没有匹配时用 agent 自己的环境变量。管理节点的出站代理（读元数据、取 logo、登记目录 URL、预览与探测镜像归档 URL、凭据测试登录）是第一条勾选了「用于管理节点出站访问」的条目。

agent 自己的请求再加上 loopback 与 server 所在地址进 `no_proxy`；同一份列表用于 agent 自己的请求、nerdctl 与 udocker 的命令行拉取（它们以前会丢掉 `NO_PROXY`）以及 dockerd 的 drop-in。目录 URL 的模型现在也经节点代理下载；内网文件服务器要写进 `no_proxy`。

节点详情里有只读的「拉取代理」卡片，显示这台节点用的是哪一条以及 dockerd 状态。代理页有「预览节点所使用代理」，按已保存的配置列出每台节点会用哪一条。接口：`/api/v1/pull/proxies`、`/api/v1/nodes/{uuid}/pull-proxy`。

### dockerd

- nerdctl、udocker 节点：每次拉取按节点代理设置，立即生效。
- docker 节点：拉取由 dockerd 执行，代理只能配在 dockerd 上。agent 把代理写进 systemd 覆盖文件并 `systemctl daemon-reload`，**不重启** dockerd。节点详情的「拉取代理」卡片显示 dockerd 实际在用的代理；与设置不一致时提示「未生效」，旁边的「重启 dockerd」确认后重启。dockerd 开了 live-restore 时容器不中断，否则节点上所有容器都会停，平台会重新拉起推理实例。

覆盖文件是 `/etc/systemd/system/docker.service.d/zz-gpuworks-proxy.conf`：

```ini
[Service]
Environment="HTTP_PROXY=http://192.0.2.8:3128" "HTTPS_PROXY=http://192.0.2.8:3128" "NO_PROXY=localhost,127.0.0.1,::1,<server 地址>,<你填的 no_proxy>"
```

文件名以 `zz-` 开头，是为了排在手写的覆盖文件（如 `proxy.conf`、`http-proxy.conf`）之后：systemd 按文件名顺序应用覆盖文件，后面的同名环境变量生效，所以拉取设置里的代理总是 dockerd 最终使用的那个。代理清空时 agent 删除这个文件，dockerd 重启前仍用旧代理，页面同样提示「未生效」。节点没有设置代理时，平台不管 dockerd 的代理（例如你自己写的 `proxy.conf`），页面只显示它当前在用的值；判断是否生效时比较的是 systemd 当前加载的配置（`systemctl show docker -p Environment`）与 `docker info`。

排障：

| 现象 | 原因与处理 |
|---|---|
| 一直提示未生效，没有重启按钮，说 `daemon.json` 优先 | `/etc/docker/daemon.json` 里配了 `proxies`，dockerd 优先用它。删掉那里的代理（或把它改成你要的值）再重启 dockerd |
| 提示需要 root | agent 不是 root，也没有免密 sudo（`sudo -n true` 失败）。按页面给出的文件内容和两条命令（`sudo systemctl daemon-reload`、`sudo systemctl restart docker`）手动执行；页面比对的是 `docker info`，执行后自动显示已生效 |
| 不是 systemd 管理的 dockerd、rootless docker、Mac 上的 Docker Desktop | 平台只展示 dockerd 的代理，不修改 |
| 代理里有用户名和密码 | dockerd 在 `docker info` 里把两者都显示为 `xxxxx`，比对时按同样方式处理 |

## 部署页看到的预估

指定了节点（单节点手动放置或多机），或自动调度已经选出节点时，逐节点显示预估：已有、从哪个节点复制、从哪些来源拉取、模型从哪里来。拉取一栏列出全部候选，例如「将从 quay.io / swr.cn-southwest-2.myhuaweicloud.com / docker.io 拉取，按节点探测速度决定最终来源」；有来源规则的替代地址时写成「先从 harbor.corp.example 拉取，不通再从 … 中按探测速度选择」。这是按当前状态算出的预估，副本启动时会重新判断。

下载过程中各处显示当前来源：镜像页的节点行显示「正在从 X 拉取」或「从节点 Y 同步」；副本启动时的状态写「pulling <实际拉取的地址>」；模型页与部署详情的模型准备显示「从 <host> 下载」（规则的替代地址之一或站点本身，切换后附原因）或「从节点 Y 复制」。

同一部署的副本可能从不同来源拉到同一 tag 的不同内容（tag 被更新过，或镜像站缓存旧内容）。部署详情逐副本显示镜像 ID，与其他副本不同的标橙色提示。

权重一栏写成「将依次从 hf-mirror.com → huggingface.co 下载」（按规则算出的候选顺序）。所有候选都被规则禁止时写「无法下载：…」，原因文字建议在有该模型的节点上登记路径，或把模型放到共享存储。这样的部署调度原因是 `weights_fetch_forbidden`（节点只能靠下载拿到模型、又被禁止）；模型页的下载接口返回 409 `WEIGHTS_FETCH_FORBIDDEN`。修改规则后会重新评估已有部署。

## 从旧版本升级

升级时自动迁移，不需要手工操作：

| 旧配置 | 迁移结果 |
|---|---|
| 全局 URL 改写（`network` 设置） | 站点规则，对所有节点生效、允许回源、勾选「用于管理节点获取模型元数据」 |
| 节点网络覆盖里的改写 | 站点规则，「适用节点」限定为 `gpuworks.ai/node=<节点 uuid>`，排在最前。旧版本里节点覆盖会整体替换全局；现在规则叠加，所以这台节点先试自己的地址，再试全局的，最后是站点本身。例如全局 hf-mirror 加某节点覆盖为内网代理，该节点的候选是 `[内网代理, hf-mirror, huggingface.co]` |
| `image_registry_rewrites` 里自己加的规则，以及节点网络设置里非 URL 的改写 | 镜像规则（节点覆盖以 `gpuworks.ai/node` 限定）；原设置含内部仓库 registry.zstack.ai 的安装会多一条 `gpuworks/ → registry.zstack.ai/gpuworks/`，可以改或删 |
| 全局代理 | 一条对全部节点生效、勾选「用于管理节点出站访问」的代理条目 |
| 节点代理覆盖 | 一条限定该节点、合并了全局值的代理条目，排在最前（这台节点仍然使用与以前完全相同的代理） |
| 代理 URL 里内嵌的 `user:pass@` | 拆成用户名和加密保存的密码 |
| 每次下载手选的端点、代理列 | 不再存在 |
| 「仓库凭据」 | 改名「凭据」，原有条目归入镜像仓库一类 |

代理在 server 启动时、加密密钥就绪后结转（迁移运行得比加密密钥早，没法在迁移里加密密码），结转在开始提供服务之前完成；结转成功后删除旧的网络设置，失败则保留旧设置、下次启动再试。

行为变化：

- 设置页的「网络」卡片、节点详情的「网络覆盖」、`/settings/network`、`network:<id>`、`/nodes/{uuid}/network`（现返回 410）、网络预设（hf-mirror、xget 预设和 DNS 建议）都已删除，不再有任何预设。
- 目录 URL 来源的模型以前不经代理直连，现在经节点代理下载。内网文件服务器要加入 `no_proxy`，否则会被送到代理上。
- 模型下载以前对同一地址最多重试 16 次；现在有候选时按上文换地址，只有最后一个地址保留 16 次。
