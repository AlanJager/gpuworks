# 通过 MCP 接入

**适用场景**：在 Claude Code、Cursor 等支持 MCP 的 AI 工具里直接问集群的情况——哪些节点离线、某个部署为什么失败、某类卡的利用率——由工具自己读平台数据作答。

**前置条件**：

- 管理员已在“设置 → MCP 服务”打开开关（默认关闭）。
- 一个平台 API 令牌，只读即可，在“API 令牌 → 平台 API 令牌”创建。

## 平台 API 令牌

控制台的“API 令牌”页有两种令牌，用途不同：

| | 推理服务令牌 | 平台 API 令牌 |
|---|---|---|
| 开头 | `gw-` | `gwp_` |
| 用来调用 | 已部署模型的 `/v1`（OpenAI 兼容） | 平台管理 API（`/api/v1/...`）与 MCP |
| 身份与权限 | 不代表任何用户 | 以创建者的身份、按其当前角色执行，再叠加令牌范围 |

平台 API 令牌的范围：

- **只读**（默认）：只能读取（GET）和调用 MCP。MCP 只需要只读。
- **读写**：能做创建者在控制台里能做的事，包括部署和删除。只给确实需要修改平台的程序。

令牌只在创建时显示一次，服务端只保存其哈希。可以设有效期（30、90、365 天或永不过期）；列表里能看到每个令牌最近一次使用的时间（每分钟更新一次）。吊销立即生效。任何令牌都不能用来查看、创建或吊销令牌，这些操作只能在登录状态下做，所以只读令牌没法给自己换一个读写令牌。创建者的角色变了或账号被删了，令牌随之变化或失效。

不用 MCP 时，令牌也可以直接调用管理 API：

```bash
curl https://<控制台地址>/api/v1/nodes -H "Authorization: Bearer gwp_..."
```

## 接入 MCP

端点是 `https://<控制台地址>/api/v1/mcp`，Streamable HTTP 传输，请求头带令牌。“设置 → MCP 服务”卡片里有带本机地址的命令，可以直接复制。

Claude Code：

```bash
claude mcp add --transport http gpuworks https://<控制台地址>/api/v1/mcp \
  --header "Authorization: Bearer gwp_..."
```

其他支持 HTTP 传输的客户端，按各自的配置文件填同样的地址与请求头，例如：

```json
{
  "mcpServers": {
    "gpuworks": {
      "type": "http",
      "url": "https://<控制台地址>/api/v1/mcp",
      "headers": { "Authorization": "Bearer gwp_..." }
    }
  }
}
```

## 提供哪些工具

与控制台里的 [AI 助手](use-ai-helper.md) 是同一套只读工具：`cluster_overview`（集群概况）、`search_api` / `call_api`（找接口、读接口，支持 jq）、`search_metrics`（指标目录）、`get_gpu_topology`（卡间互联）、`compare_with_healthy_replica`（失败实例与健康副本的差异）。读到的数据与令牌所属用户在控制台上看到的一样，交出之前同样做凭证脱敏和截断。MCP 不提供任何写操作，与令牌范围无关。

同一用户同时最多 4 个工具调用在执行，再多的调用会收到「请稍后」的结果。每次工具调用都在 server 日志里记一条 `mcp tool call`（用户、令牌前缀、工具、耗时）。

## 数据去向

MCP 客户端会把读到的平台数据交给它自己配置的模型。数据发往哪里由客户端决定，和平台“设置 → AI”里配置的模型无关。在意数据出境时，请让客户端使用你认可的模型，或保持 MCP 关闭。

## 排查

| 现象 | 原因 |
|---|---|
| 403 `MCP_DISABLED` | MCP 服务没开，请管理员在设置页打开 |
| 401 | 令牌错误、已吊销、已过期，或所属账号已删除 |
| 403 `PLATFORM_TOKEN_READ_ONLY` | 用只读令牌做了写操作（直接调管理 API 时）；MCP 本身不会出现 |
