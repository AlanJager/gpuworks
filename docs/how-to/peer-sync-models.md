# 在节点之间同步模型和镜像

**适用场景**：某台节点已经有完整的模型或推理镜像，要把它直接同步到另一台节点，不走公网下载，也不经过 server 中转；或排查节点间同步失败（`NO_STORAGE_PATH`、直连测试不通、停在 `download_required`）。

节点间复制有两种触发方式：**自动**——副本启动时本机没有，同一[同步组](configure-pull-settings.md#同步组)里有在线节点持有就自动复制，复制失败则改为自己拉取或下载，不需要操作；**手动**——在模型页或镜像页显式选源节点，本页主要讲这种，不受同步组限制。

**前置条件**：

- 源节点和目标节点都在线，见[接入节点](connect-nodes.md)；源节点持有完整副本（模型为 `present`，镜像已存在于运行时）。
- 两端有共同的存储同步网络，或都允许管理网承担存储同步，见[配置节点网络](configure-networks.md)。
- 自动复制只发生在同组节点之间，分组与限速见[配置镜像拉取](configure-pull-settings.md#同步组)。
- 模型的注册与其他获取方式见[下载、缓存和节点间同步模型](download-and-sync-models.md)。

节点间同步（peer sync）的原理：目标 agent 起一次性 TLS 接收端，源 agent 直连发送（模型是目录 tar，镜像是运行时导出的镜像归档）。server 只协调端点和一次性凭据，不中转字节；传输必须带具体 transfer ID。模型完成后目标节点重新校验 manifest，镜像以目标运行时导入完成且 `ImageExists` 为真为准。

## 同步一个模型或镜像

1. **选目标和源节点。** 在模型页对应行用「同步到其他计算节点」，镜像在镜像详情页的节点行操作。**必须显式选择源节点**，它是唯一候选：源节点离线或副本已不完整时，同步失败或停在 `download_required`，由你重新选择，不会静默换成另一台节点、server 中转或公网下载。
2. **先点「测试直连」。** 它调用 `.../sync/probe`，在目标起临时接收端，让源节点完成一次真实的 TLS 与令牌握手，不传字节、不写同步记录。探测通过后才允许点同步；后端同步时仍会重新握手。
3. **按需填限速。** 每次同步单独填写 MiB/s，留空或 0 为不限速（API 字段 `rate_limit_kib_s`，单位 KiB/s）；多目标时每个目标各自限速。
4. **发起同步并观察进度。** 任务结束后清除活动限速，失败记录保留上次限速供重试预填。
5. **失败时重试或取消。** 重试沿用失败记录里的源节点和上次限速，见下文[重试与恢复](#重试与恢复)；取消会停止目标节点上的接收与 `docker load`。

## 走哪张网

两个节点之间用哪张网由 server 按节点对选定，规则见[配置节点网络](configure-networks.md)：

- 两端共同的存储同步网络优先；否则两端都允许管理网承担存储同步时走管理网。
- 目标只在该网络的地址上接收，源节点从本端在该网络的地址发起，并按一次性证书指纹校验。
- 两端没有可用的共同网络时报 `NO_STORAGE_PATH`；自动复制会跳过该源，副本改为自己拉取或下载；手动指定该源时报该错误。能否连通以「测试直连」为准。
- 自动复制时直连失败（约 10 秒）的节点对，server 在内存里冷却 3 小时，期间不再尝试复制；重启 server 清空冷却。

## 镜像在不同运行时之间同步

Docker、nerdctl 与 runveil 节点之间镜像可互为源和目标。runveil 导出的是 OCI 布局加 `manifest.json` 的归档（与 Docker 29 `docker save` 同形），层按 registry 原样的压缩字节发送，manifest digest 在两端一致；它只能发送自身镜像存储里完整的镜像，旧 udocker CLI 登记的镜像需重新拉取或导入。

## 重试与恢复

- 重试沿用失败记录里的源节点和上次限速；后台协调不会自动重试已失败的手动选源任务。
- 镜像同步在 server 或节点重连后，若该传输两分钟内仍有进度则沿用原传输，否则用原源节点和限速从零重新开始。
- 公网下载失败后，若有在线节点持有完整副本，仍可再手动走一次节点间同步，不会永久卡在失败状态。
