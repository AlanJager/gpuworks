# 下载、缓存和节点间同步模型

**适用场景**：要注册模型、了解部署时权重与镜像怎么到达节点（本地已有、同步组内复制、下载），或把已有模型 / 镜像从一台节点同步到另一台节点。

**前置条件**：

- 目标节点在线，见[接入节点](connect-nodes.md)。
- 公网下载：节点能访问所选来源（Hugging Face 或 ModelScope），或在拉取设置里为它配置了代理、站点规则（镜像站、内网代理），见[配置镜像与模型拉取](configure-pull-settings.md)。
- 节点间同步：至少有一台在线节点持有完整副本，并且两端网络可直连（自动复制还要求同在一个同步组），完整前置条件见[在节点之间同步模型和镜像](peer-sync-models.md)。

注册模型时指定 `source`（`huggingface` 或 `modelscope`）和 `source_id`（如 `Qwen/Qwen3-8B`），
并固定 revision；ModelScope 的 `main` 会归一为 `master`。注册弹窗没有默认来源：填好仓库 ID
后可以检测两家公共仓库分别有没有该模型，再显式选一个。“未找到”和“无法检测”是两种不同的
结论，后者仍然可选。

agent 通过可续传、多连接、限速 HTTP 下载，完成后以原子 marker
记录完整 manifest。只有所有文件存在、大小匹配且目录结构有效时才报告 `present`。
下载没有任务级截止时间。单个 HTTP 请求最长 15 分钟，连续 5 分钟收不到数据的连接会提前放弃；两种情况都按传输层超时从已下载的部分续传重试。

服务器按节点算出候选地址（站点规则的替代地址在前，站点本身在后），节点逐个尝试：连接或 TLS 错误、任何 HTTP 错误（含镜像站缺这个仓库的 404、401/403）会让该地址冷却 30 分钟并换下一个；同一地址连续 2 次卡住也换。后面还有候选的地址最多重试 6 次，最后一个地址保留 16 次。版本固定为 commit 时换地址接着续传，否则从头开始。进度显示「正在从 <host> 下载」，切换后附原因，细节见[配置镜像与模型拉取](configure-pull-settings.md#节点怎样依次尝试)。目录 URL 来源的模型只从自己的目录下载，规则不作用于它们，但会经节点代理。

## 登记节点已有目录

模型详情中的“注册节点路径”用于采用已经放在节点上的文件。填写节点宿主机上的绝对目录路径；
可以指向本地存储根目录之外的位置，不需要先把已有模型搬进下载目录。选择的本地存储用于记录归属，
登记不会复制或移动文件。

节点会检查目录可读、有非空文件且没有未完成下载。缺失、空目录或包含 `.part` 文件时登记失败，
已有登记保持原样。为兼容自定义引擎，登记不要求固定模型文件名；“已登记”也不表示模型格式正确或能被引擎加载，
请选择实际准备部署的模型目录。具体请求和状态码见 [API 契约](../reference/api.md#登记节点已有路径)。

登记路径还会用该目录补齐模型缺失的元数据（config、README、大小），已有的元数据不覆盖。目录是用 `huggingface-cli download --local-dir` 下载的、`.cache/huggingface/download/*.metadata` 全部指向同一个 commit，并且这是该模型唯一的一份副本时，模型会固定到这个 commit。这是离线导入的做法，见[离线导入模型](configure-pull-settings.md#离线导入模型)。

## 部署时怎么取到模型和镜像

部署不选择权重和镜像从哪里来（[ADR 0048](../adr/0048-pull-settings.md)）。部署页“获取”一栏只有两个问题：

1. **权重来源**——模板声明了多个来源时，选运行 Hugging Face 还是 ModelScope 的权重，模板建议的那家预选。
2. **保存到**——节点需要取模型时保存到哪个存储，候选来自 evaluate 的 `targets`；已经有该模型的存储显示为已持有（`present`），不会再下载。

所选值随部署请求以 `model_source: {storage_id, provider}` 提交。

每台节点在副本启动时自己决定怎么拿到模型：

- 节点本地或它能读到的共享存储里已有完整副本，直接使用；
- 同一[同步组](configure-pull-settings.md#同步组)里有在线节点持有，就从它复制；
- 否则按所选来源下载，下载地址受[站点规则与节点代理](configure-pull-settings.md)影响；规则把所有候选都禁止时，部署的调度原因是 `weights_fetch_forbidden`，下载接口返回 409 `WEIGHTS_FETCH_FORBIDDEN`。

自动调度的部署，页面只显示“镜像和模型在调度后按拉取设置自动获取”；指定了节点（手动放置或多机）时，逐节点显示预估：已有、从哪个节点复制、按什么顺序拉取镜像或下载模型。这是按当前状态算出的预估，节点启动时会重新判断。

“本地已有”按模型身份判定而非下载源：同 repo 且 revision 相同，或跨源 revision 不同但权重
字节、架构与上下文长度一致。

镜像走同一套判断：本地已有时直接使用；同步组内的其他在线节点已有时复制；否则按候选依次拉取，候选来自镜像的等价副本
（模板自己声明的 `image_sources`、镜像目录登记的来源、镜像自身的地址）和适用于该节点的来源规则，见
[配置镜像拉取](configure-pull-settings.md)。模板声明的来源见
[模板语法](../reference/inference-catalog-spec.md#image_sources模板声明的镜像来源)，使用它们不算偏离模板。
已缓存的镜像不再占用调度的运行时磁盘估算。

## 节点间同步

已有模型或镜像可以从一台节点直接同步到另一台节点：目标 agent 起一次性 TLS 接收端，源 agent 直连发送，server 只协调、不中转字节。同步组内的节点在副本启动时会自动这样复制；在模型页或镜像页手动同步时必须显式选择源节点，不受同步组限制，同步前先用「测试直连」确认两端能连通，每次同步可单独限速；公网下载失败后，只要有在线节点持有完整副本，仍可再走一次节点间同步。选网规则、限速、重试与恢复、runveil 镜像互通等细节见[在节点之间同步模型和镜像](peer-sync-models.md)。

失败可重试或取消，不能把 partial 目录直接注册为 present。节点本地驱逐使用
`DELETE /api/v1/models/{id}/nodes/{uuid}`，活动部署使用中的模型会返回 409。
