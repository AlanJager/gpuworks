# 配置节点网络

**适用场景**：节点有多张网卡或 RDMA 网卡时，指定存储同步、参数（多机推理与 PD 的 KV 传输）、服务三类流量各走哪张网；或排查节点间不通、NCCL/RDMA 配置和带宽问题。

**前置条件**：

- server 已运行，相关节点已按[接入节点](connect-nodes.md)接入并上报网卡清单。
- 使用 RDMA 网络时，节点上要有 ACTIVE 的 RDMA 端口（InfiniBand 或 RoCE，RoCE 端口所在网卡需要 IPv4 地址）；`ib_write_bw` 带宽测试依赖宿主机的 rdma-core / MLNX_OFED 用户态库，或 perftest。
- 参数网络有三种类型：主机以太网、主机 RDMA（NVIDIA，NCCL/UCX）和加速器 RDMA（昇腾，HCCL）；多机推理和 PD 的用法见[多机推理](multi-node-inference.md)与 [PD 分离部署](pd-disaggregation.md)。

「资源 → 网络」页声明节点之间用哪张网卡走哪类流量。设计取舍见 [ADR 0030](../adr/0030-network-objects.md)；RDMA 网络的自动推断见 [ADR 0027](../adr/0027-rdma-network-inference.md)。

## 监听地址与「别人怎么连过来」

server 自己不存、也不推断对外地址（见 [ADR 0025](../adr/0025-server-holds-no-external-address.md)）。
设置页「监听地址」卡片（即 `server.yaml` 的 `listen.*`，修改方法见[配置参考](../reference/configuration.md#在控制台修改监听地址)）只决定 server 在**本机**绑定哪些 `IP:端口`；别人用域名、反向代理还是 NAT 转发连过来，由调用方自己选择。
UI 里需要填 server 地址的地方都用浏览器当前访问的地址预填，可以改成域名或反代地址；API 对应字段 `server_url` 必须显式传入。
改 `listen.agent` 会影响**已装**的 agent：它们只拨打安装命令里那个地址，该地址不再转发到新监听地址时就会离线，直到转发修好或重装。

「资源 → 网络」页顶部的「网络拓扑与配置」卡片用一张简单拓扑和一张复杂拓扑，把每一项配置画在图上
并配一张编号对照表：在哪里设置、起什么作用、不决定什么；把鼠标移到编号或表格行上会互相高亮，
不熟悉这套地址概念时建议先看这张图。

## 网络

一个网络包含：

- **角色**（可多选）：`存储同步`（节点间同步模型和镜像）、`参数`（多机推理的 NCCL/Gloo 与 PD 分离的 KV 传输）、`服务`（网关访问推理实例）。三个都选就是 all in one。
- **类型**：`主机以太网`（`host_ethernet`）、`主机 RDMA`（`host_rdma`）或 `加速器 RDMA`（`accelerator_rdma`）。主机 RDMA 同时涵盖 InfiniBand 和 RoCE，每个节点是哪一种由其 RDMA 端口的链路层自动识别，显示在节点行上；同一网络内识别出不同链路层时给出橙色叹号。加速器 RDMA 是加速卡自带的 RoCE 口（昇腾 NPU），见[下文](#加速器-rdma-网络加速卡自带的网口)。类型决定参数网络的 NCCL/UCX/HCCL 配置和设备注入。只有同一个网络对象上的节点被视为互通。
- **默认选择器**（只有主机以太网需要）：填"默认网段"，流量走地址落在其中的网卡；网卡名（支持 `*`、`?`、`[...]` 通配）只在网段区分不开时需要。
- 主机 RDMA 与加速器 RDMA 网络**不需要填写任何选择器**，见下两节；"高级"里只有一个可选的 bootstrap 网段。

### RDMA 网络：bootstrap 与 HCA 自动推断

RDMA 网络上每个节点用两样东西：

- **HCA**（rail）：承载数据的 RDMA 端口，如 `mlx5_0:1`。RoCE 端口的 **HCA IP** 是它所在网卡的 IPv4 地址，RoCE v2 靠它建立连接；InfiniBand 端口不需要 IP，显示"—"。
- **bootstrap IP**：握手用的 TCP 地址（NCCL 带外通道、Gloo、vLLM master 地址、ib_write_bw 交换连接参数），数据不经过它。它可以不在 RDMA 网卡上。

加载节点后，按 agent 上报的网卡清单为每个节点推断：

| | 规则 |
|---|---|
| HCA | 取状态为 ACTIVE 的端口；节点上有 InfiniBand 端口时只取 InfiniBand，否则取 RoCE；RoCE 端口要求所在网卡有 IPv4 地址；只保留速率最高的一组（RoCE 按网卡速率），例如排除 1G 管理口 |
| bootstrap | 依次取：节点上指定的 bootstrap；网络填了 bootstrap 网段时，地址落在其中的网卡（没有命中就留空并告警，不回退）；第一条 HCA 所在网卡的地址；没有 IPoIB 的 InfiniBand 用管理网地址 |

网络详情的节点列表按节点列出 bootstrap IP 和成组的 HCA 与 HCA IP，旁边标"自动"或"手动"：

- 每条 HCA 旁的 ✕ 移除它，默认从网络上**所有**用它的节点移除（各节点的 HCA 要一一配对），可勾选"只从本节点移除"；「添加 HCA」从该节点上报的端口里选，不可用的端口写明原因（未激活、网卡没有 IPv4 地址）。第一次增删后，该节点的 HCA 固定为当时的列表（"手动"），不再随网卡清单变化；「恢复自动」回到推断。节点最后一条 HCA 不能移除，不再使用时请卸载该节点。
- bootstrap 的「修改」从该节点带地址的网卡里选，「恢复自动」清除。
- 这些修改只写在节点的加载项上；经标签加载的节点第一次修改时会为它生成一个节点加载项。

推断出的节点会带上这些提示（橙色叹号）：没有可用的 RDMA 端口、没有 bootstrap 地址、手动指定的 HCA 不可用、各节点 HCA 数量不一致。

### 加速器 RDMA 网络：加速卡自带的网口

昇腾 910 每张卡自带一个 RoCE 口，主机内核看不到它（不在网卡清单的网卡和 RDMA 端口里），只能用 `hccn_tool` 访问。昇腾跨机的集合通信（HCCL）只走这些口：没有开关能让它改走主机网卡，也不会自动回退，所以**昇腾多机部署必须使用加速器 RDMA 网络**，否则被拒绝（`COMPUTE_NETWORK_ACCELERATOR_REQUIRED`）。

加速器 RDMA 网络上每个节点同样用两样东西：

- **rail**：加速卡，写作 `npu3`（3 号卡）。地址、链路状态和速率由 agent 用 `hccn_tool` 读取，每分钟刷新一次；节点详情「网卡清单」的「加速卡网口」表列出全部。
- **bootstrap IP**：握手用的主机地址（HCCL 建通信域、Gloo、vLLM master 地址）。主机进程无法绑定加速卡网口的地址，所以它一定是主机网卡上的地址。

| | 规则 |
|---|---|
| rail | 链路 UP 且配了 IPv4 地址的加速卡，按卡号排列 |
| bootstrap | 依次取：节点上指定的 bootstrap；网络填了 bootstrap 网段时，地址落在其中的主机网卡；管理网地址 |

增删 rail、修改 bootstrap、"自动 / 手动"的含义与主机 RDMA 网络相同；「添加 HCA」列出的是该节点的加速卡。

它**只能承担参数角色**：存储同步和服务都是主机进程，绑不了加速卡网口的地址。表单里这两个角色置灰，API 返回 `NETWORK_TYPE_ROLE_INVALID`。

网络只声明"这些节点的加速卡网口连在一起"，不决定实例用哪几张卡：实例用调度选中的卡，哪两张卡之间能通取决于布线。两台机器按卡号直连时只有同号卡之间能通，而这从地址上看不出来（两台的卡可以在同一个网段里）。

### 加载到节点或标签

网络可以加载给任意个节点和节点标签（`key=value`）。每个节点每个角色最终只用一个网络：

1. 直接加载到节点的优先于经标签加载的。
2. 同一优先级命中多个同角色网络时，先加载的生效。节点详情页和网络详情页的节点列表会在该节点旁显示橙色叹号，悬停可以看到没有生效的网络。

「加载」可以一次选多个节点；个别节点失败（例如节点已删除）不影响其他节点，结果里逐个列出，已经加载过的节点算成功。

主机以太网加载到节点时可以覆盖默认选择器：指定网卡或 IP。主机 RDMA 与加速器 RDMA 网络在节点上可以指定 bootstrap 网卡或 IP（见上两节），HCA 在节点列表里增删。覆盖值会用 agent 上报的网卡清单校验，清单里没有时同样显示橙色叹号。节点离线时也能保存。

节点详情页的「已加载网络」列出这个节点每个角色实际用的网络、网卡、IP 和 HCA；「网卡清单」是 agent 从 sysfs 读取的网卡、地址、速率和 RDMA 端口，以及昇腾节点上用 `hccn_tool` 读取的加速卡网口。只上报物理网卡和带地址的虚拟网卡（网桥、bond、VLAN）。

### 管理网

每个节点都在内置的**管理网**上：节点连接 server 所用的本机地址（经 127.0.0.1 或 HTTP 代理连接时，改用默认路由所在网卡的地址），由 agent 自动上报。管理网没有对应的网络对象，不能删除、修改或加载；它排在网络列表第一行。某个角色没有加载任何网络时，由管理网承担。每个节点可以分别关闭「管理网可承担存储同步 / 参数同步 / 服务」，默认全部开启，只对新实例生效（需要管理员）：

- 管理网详情页的节点表每个角色一列开关，可逐个切换；角色开着但已由独立网络承担时，开关旁注明「由独立网络承担」。
- 同一页可按名称、地址搜索，按节点标签筛选，勾选节点（或「选中筛选结果」）后批量设置：每个角色选「保持不变 / 允许 / 禁止」，只修改选中的角色，全部节点一起成功或一起失败。
- 节点详情「网络」页的「管理网」卡片也能切换本节点的角色。管理网承担服务时走 agent 隧道，不启用服务网络转发。

「管理网」卡片还显示 server 看到的连接来源；它与管理网地址不同时标「经 NAT 接入」，只作展示。

### 各角色怎么生效

| 角色 | 生效方式 | 没有网络或没匹配到网卡时 |
|---|---|---|
| 存储同步 | 节点间复制模型和镜像按节点对选网络（自动复制只发生在同一[同步组](configure-pull-settings.md#同步组)内，手动同步不受此限）：两端共同的存储同步网络优先，否则两端都允许管理网承担存储同步时走管理网。接收端只在所选网络的 IP 上监听，发送端从本端在该网络的 IP 发起；同步源候选中，与目标同属一个存储同步网络的节点排在最前并被推荐 | 两端没有可用的共同网络时不做节点间直连，自动复制会跳过该源，副本改为自己拉取镜像或下载模型；手动指定该源时报 `NO_STORAGE_PATH` |
| 参数 | 多机部署每个 rank 用该网络的 IP 作为 `VLLM_HOST_IP` 与 master 地址；主机类型注入 `NCCL_SOCKET_IFNAME`/`GLOO_SOCKET_IFNAME`；主机以太网设 `NCCL_IB_DISABLE=1`；主机 RDMA 设 `NCCL_NET=IB`、`NCCL_IB_HCA`（全部 HCA）、`UCX_NET_DEVICES`（第一张 HCA），并给容器加 `--device /dev/infiniband --ulimit memlock=-1 --cap-add IPC_LOCK`；加速器 RDMA 设 `HCCL_IF_IP`（bootstrap IP）、`HCCL_SOCKET_IFNAME`/`GLOO_SOCKET_IFNAME`（bootstrap 网卡），并把主机的 `/etc/hccn.conf` 只读挂进容器，不加 `/dev/infiniband`。多机组按整组选网络：所有节点共同的参数网络优先，否则所有节点都允许管理网承担参数同步时走管理网 | 管理网（以太网，按管理网卡设置 `NCCL_SOCKET_IFNAME`/`GLOO_SOCKET_IFNAME`、`NCCL_IB_DISABLE=1`） |
| 服务 | agent 在服务 IP 的 `19443` 端口起 TLS 转发；网关用每个实例的令牌连过去，转到实例的回环端口。在服务网络上的节点**只**经服务网络访问，不回退隧道：实例调度到节点后、启动容器前，server 会连一次该端口并完成 TLS 握手，不通就让实例失败并写明原因；已运行的实例在网络不通时请求直接失败。这次拨号不绑定源地址，走本机路由表的选择（同网段有服务网络网卡时通常就是它）。节点详情「服务网络转发」显示地址与状态（不可达时悬停看原因） | 管理网承担服务时走 agent 隧道；节点关闭了「管理网可承担服务」又没有服务网络时，调度不会把实例放到该节点（`serving_unavailable`） |

参数网络的约束：

- 多机部署的所有节点共用同一个参数网络时用它；否则（有的在参数网络上、有的不在，或在不同的参数网络上）整组回退到管理网，评估时给出 `COMPUTE_NETWORK_FALLBACK` 提醒。某个节点不允许管理网承担参数同步、又无法共用参数网络时，部署被拒绝（`COMPUTE_NETWORK_NONE` / `COMPUTE_NETWORK_MIXED` / `COMPUTE_NETWORK_MISMATCH`）。想避免回退，就在这些节点上关闭管理网可承担参数同步。多机实例详情的「参数网络」一行显示该 rank 启动时实际用的网络、网卡和 IP，走管理网时标明是回退。
- 主机 RDMA 参数网络不能用在 udocker 节点上（`COMPUTE_NETWORK_RUNTIME`），因为 udocker 无法向容器暴露 RDMA 设备。
- 主机 RDMA 类型强制走 IB 传输：容器看不到 verbs 设备时启动直接失败，而不是静默退回 TCP。模板或用户设置的同名环境变量仍然优先。
- 昇腾节点的多机部署必须共用一个加速器 RDMA 网络（`COMPUTE_NETWORK_ACCELERATOR_REQUIRED`），且每个节点在上面至少有一张可用的卡（`COMPUTE_NETWORK_NO_CARDS`）。
- PD 分离按模式的 KV 传输方式检查网络：走加速卡网口的模式（`vllm-ascend-mooncake`）跨机时必须在加速器 RDMA 网络上（`PD_NETWORK_ACCELERATOR_REQUIRED`）；走 UCX 的模式不能用加速器 RDMA 网络（`PD_NETWORK_HOST_REQUIRED`）；可休眠的 PD 部署不能让 KV 走主机 RDMA 网络（`PD_SLEEP_RDMA_UNSUPPORTED`，见 [sleep / wake](sleep-wake.md) 的限制），创建时拒绝，之后再挂上 RDMA 网络时部署停在无法调度并给出同一原因。普通多机部署经 RDMA 网络走集合通信不受此限。

服务网络转发的令牌是 `HMAC(节点 token, 实例 UUID)`，TLS 密钥也由节点 token 派生，两者都不落库、不在界面显示，调试时请带 API key 走网关。防火墙需要放行 server 到节点服务 IP 的 `19443/tcp`。

网络、加载关系或节点标签变化后，server 会给在线节点重新下发配置。运行中的实例不受影响，下次启动才用新网络。

## 节点代理与下载地址

节点出网用的代理（`http_proxy` / `https_proxy` / `no_proxy`）和模型、镜像的下载地址（镜像站、内网代理、禁止回源）不在这里配，它们与上面的存储同步 / 参数 / 服务网络是不同的东西：在设置 → 拉取设置里按节点标签配置，分别是「代理」和「来源规则」。节点详情有只读的「拉取代理」卡片，显示这台节点实际用的代理和 dockerd 状态。规则、代理、示例与排障见[配置镜像与模型拉取](configure-pull-settings.md)，docker 节点的 dockerd 代理见[其中的 dockerd 一节](configure-pull-settings.md#dockerd)。

agent 每 10 秒采集各网卡与 RDMA 端口的收发速率、错误与拥塞，以及按角色的节点流量。指标名称、标签和口径见[网络监控指标](../reference/network-metrics.md)。

- 节点详情「网络」页的网卡清单和 RDMA 端口表显示最近两分钟的实时速率。
- 网络详情页（含管理网）的「监控」标签页按节点画出该网络的流量、错误与拥塞，可选 15 分钟到 24 小时。

## 内部测试

存储同步网络、参数网络和管理网的详情页有「内部测试」标签页。管理网上的节点是所有已上报管理网地址的节点，测的就是各节点连 server 所用的地址（即使独立网络接管了它的全部角色）；管理网是以太网，可以跑 TCP 和 NCCL 镜像测试，不能跑 ib_write_bw。范围可以选：

- 网络上的全部节点；
- 指定节点；
- 按标签筛选。

测哪些节点对：

- **全互测**：每个有序节点对都测，N 个节点共 N×(N−1) 对、分 N−1 轮。
- **环形**：节点按名称排成一圈，每个节点只测下一个，最后一个测第一个，共 N 对、一轮完成。每个节点恰好发、收各一次，能发现单个节点或单条 HCA 的问题；发现不了只在不相邻节点之间才出现的不通（例如 fabric 被分成两半而相邻节点恰好在同一半）。超过 16 个节点时默认选环形。

每对从源节点在该网络上的地址，连接目标节点在该网络上的地址上的临时端口，测认证握手的 RTT，可选再测几秒 TCP 吞吐。每轮每个节点只收发各一路。

结果先给出**问题汇总**：按"哪个节点的哪条 HCA、什么原因"合并失败，写明影响几对；HCA 引起的问题可以直接「移除 HCA」，重新测试后生效。下面是节点矩阵（全互测）或节点对列表（环形），节点对分"通过 / 部分通过（部分 HCA 失败）/ 失败"，点击（或回车）打开该对的详情：源、目标地址、RTT，RDMA 测试还列出每条 HCA 的源与目标、各自的 IP 和结果。发起前会列出没有地址（RDMA：bootstrap）或没有可用 HCA 的节点。每个网络保留最近 10 次结果。

RDMA 网络可以选测试方式：

- **TCP**：同上，走 bootstrap 网卡。
- **RDMA 带宽（ib_write_bw）**：每对节点先在目标节点的 HCA 上起服务端，再从源节点的 HCA 连过去，各 HCA 并行运行，带宽为各 HCA 之和。两端 HCA IP 在同一子网的优先配对（点对点 /30、/31 的接法），其余按顺序配对；多出来的 HCA 以"对端没有可配对的 HCA"失败。RoCE 端口使用 IPv4 的 RoCE v2 GID（与 NCCL 2.21 及以上的默认选择一致）；网卡没有 IPv4 地址的 RoCE 端口直接以此为原因失败，不再交给工具自选 GID。握手走目标节点的 bootstrap 地址。

  工具的来源依次是：宿主机 `PATH` 上的 `ib_write_bw`；agent 内置的 `ib_write_bw`（动态链接宿主机的 `libibverbs`、`librdmacm`，只要装了 rdma-core 或 MLNX_OFED 这类 RDMA 用户态库就能运行）；都不能运行时对应节点对以"没有可运行的 ib_write_bw，请安装 perftest"失败，发起前会列出这些节点。安装 perftest 时包管理器会一并装上用户态库。

  NCCL 低于 2.21 的自定义镜像默认用 GID index 0（RoCE v1），与测试走的路径不同；这类镜像在 RoCE 网络上需要自行设置 `NCCL_IB_GID_INDEX`。

加速器 RDMA 网络可以选：

- **TCP**：同上，只验证握手用的 bootstrap 地址，不经过加速卡网口。
- **卡连通性 · 同号卡**（`card_ping`，默认）：两个节点的同号加速卡互相 ping（`npu3` 对 `npu3`）。适合日常巡检。
- **卡连通性 · 全卡矩阵**（`card_matrix`）：一个节点的每张卡 ping 另一个节点的每张卡。哪张卡能通哪张卡是布线事实，从地址上看不出来；建网时用它测出来。

卡连通性测试由 agent 在宿主机上用 `hccn_tool -i <卡号> -ping` 发起，只测可达性，不测带宽。ping 有回包，一次探测就证明了双向，所以每两个节点只测一次：全互测共 N×(N−1)÷2 对，环形 N 对。

**耗时取决于轮数，不取决于探测数。** 一张卡同一时间只发一次 ping（同一张卡并发多个会让它在一段时间内报错），不通的地址要等满 3 秒超时，所以一轮最长 3 秒，与节点数无关。节点对按轮次错开（第 k 轮节点 i 测节点 i+k），卡也一样（第 s 次移位时源节点的第 c 张卡测目标节点的第 c+s 张卡），每一轮里每张卡恰好当一次源、一次目标：

| 24 个节点 × 8 张卡 | 探测数 | 轮数 | 最长耗时 |
|---|---|---|---|
| 环形 + 同号卡 | 192 | 1 | 3 秒 |
| 环形 + 全卡矩阵 | 1536 | 8 | 24 秒 |
| 全互测 + 同号卡 | 2208 | 12 | 36 秒 |
| 全互测 + 全卡矩阵 | 17664 | 96 | 4.8 分钟 |

表单在发起前显示节点数、探测数、轮数和最长耗时，这些数字由 server 按"将要怎么跑"算出（`POST /networks/{id}/tests/estimate`，与发起用同一套校验）；轮数 × 3 秒超过 10 分钟的组合不能发起（`NETWORK_TEST_TOO_LONG`），请缩小范围或改用环形、同号卡。

结果先用一句话回答"部署时该怎么选卡"，它由每个节点对的形状得出。形状由 server 从这次测试的逐对结果读出，随结果一起返回（`card_shape`），不单独存储；它是**测试那一刻**的情况，布线或链路变化后需要重测：

| 形状 | 含义 | 结论 |
|---|---|---|
| 全互通 | 每对卡都通 | 任意卡号组合可用 |
| 仅同号卡 | 只有同号卡之间通（按卡号直连，或按卡号分平面） | 两端必须选相同卡号 |
| 部分可达 | 其他情况 | 布线不规则，按各节点对的结果选卡 |
| 全不通 | 没有一对卡通 | 检查加速卡网口的链路与地址 |
| 未测 | 节点离线、没有卡，或没有同号卡可测 | 看该节点对的原因 |

节点对的"通过 / 部分通过 / 失败"按形状计：全互通与仅同号卡算通过（都是可部署的形态），部分可达算部分通过，全不通与未测算失败。

多数节点对是同一形状时给出这个形状的结论，并**点名与其余不同的节点对**，那通常就是要找的布线或配置问题。下面是节点对总览（全互测是节点 × 节点的表，环形是列表），每格是该节点对的形状；点击（或回车）打开该节点对：全卡矩阵是"源卡 × 目标卡"的网格，同号卡是逐对卡的列表，悬停看两端地址、RTT 或失败原因。只测了一个节点对时直接显示这张网格。

TCP 与 RDMA 带宽测试在 agent 宿主机上执行，走的是存储同步和 host 网络下以太参数网络的真实路径；容器内推理 rank 之间的 NCCL 路径不在内部测试范围内。全互测一次最多 128 个节点，环形最多 1024 个；server 重启时正在进行的测试会标记为中断。
