# 多机推理

**适用场景**：模型单节点放不下，或希望把 TP / PP 拆到多台节点上，让一个部署的多个 rank 分布在多台机器。

**前置条件**：

- 至少两个在线节点，已按[接入节点](connect-nodes.md)接入。
- 所有节点共用同一个参数网络，或都允许管理网承担参数同步；节点间所选网络的地址上 TCP 双向放行。选网与 RDMA 设置见[配置节点网络](configure-networks.md)，其中主机 RDMA 参数网络面向 NVIDIA（NCCL/UCX），不能用在 runveil（udocker driver）节点上；昇腾多机必须使用加速器 RDMA 网络。
- 已熟悉单机部署流程，见[部署模型、选卡与解释调度结果](deploy-models.md)。

整组 rank 用同一个网络互联：所有节点共同的参数网络，否则所有节点都允许时用管理网（节点连
server 所用的本机地址，自动上报），并按网络类型配置 NCCL/UCX/HCCL 与 RDMA 设备，见
[配置节点网络](configure-networks.md)。没有可共用的网络时部署被拒绝。昇腾节点的多机部署必须共用一个
加速器 RDMA 网络：昇腾跨机的集合通信只走加速卡自带的网口。

1. 确认各节点在所选网络上的地址之间，防火墙允许双向 TCP。
2. 在部署页按 rank 0…N-1 固定节点顺序，并设置并行方式：张量并行（TP）和流水线并行（PP）
   都是整个部署的值，总卡数 = TP × PP，每个节点运行 TP × PP ÷ 节点数 张卡（必须整除）。
   选好节点后默认 TP = 所选节点中最少的 GPU 数、PP = 节点数；TP 也可以跨节点，例如两台各
   1 张卡的节点用 TP 2。GPU 多于每节点卡数的节点只用其中一部分。vLLM 传
   `--tensor-parallel-size TP`（PP > 1 时加 `--pipeline-parallel-size PP`），SGLang 传
   `--tp-size TP`（PP > 1 时加 `--pp-size PP`）。部署表单在多机模式下把并行度放在节点之后、
   镜像之前；并行度填错只标在 TP / PP 上，不影响镜像和权重获取预估的计算。
3. 镜像和权重由各节点按[拉取设置](configure-pull-settings.md)自行获取，已有镜像或权重的节点直接跳过。表单逐节点显示预估（例如
   "2 个节点中 1 个需要拉取镜像"），可展开看每个节点的镜像与权重状态；多机部署启动前会按同一份候选预拉取镜像。
4. 提交前调用 `POST /api/v1/deployments/preflight`。平台为每个节点启动一个带一次性
   token 和 TTL 的临时 sink（供其余节点探测复用），测认证握手与 TCP 接收带宽，完成后立即关闭。
5. 确认 master 端口空闲。rank 0 的地址作为 master；vLLM follower 使用 headless，SGLang
   follower 使用运行时要求的内部 health 端口，对外流量只进入 rank 0。

一个副本的全部 rank 作为一个整体放置：控制器先为每个 rank 试算（模型与镜像就绪、端口、GPU 与显存），
全部放得下才在同一个事务里创建全部实例；任何一个放不下时一个实例都不创建，leader 不会先占着卡，也不计入副本的重试次数。
部署时间线记 `DEPLOYMENT_UNSCHEDULABLE`，内容是调度原因以及放不下的 rank 序号与节点（`rank`、`node`）；资源到位后自动启动，
无需操作。PD 部署的多机单元同样如此。

已有多机部署加副本时，在部署详情「调整副本」里点「添加推荐副本」：平台从可调度、在线、满足节点条件的节点里挑出共享同一计算网络和
GPU 架构、各有一个 rank 空闲卡的一组，按部署配置逐 rank 试算后填进列表（leader 不与其他副本的 leader 同节点），确认无误再保存；
挑不出时说明各类节点被排除的数量。平台不会自动替多机副本选节点——跨交换机、RDMA 不通的代价比单机大得多。

预检查失败应先修正路由、防火墙或端口，不要通过关闭认证绕过。完整创建字段见
[API 参考](../reference/api.md)。
