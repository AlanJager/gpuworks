# 从 HTTP 文件服务器导入模型与镜像

**适用场景**：模型目录或 `docker save` 归档放在内网 HTTP 文件服务器（Apache / nginx / Caddy 的 autoindex 列表页）上，不走 Hugging Face、ModelScope 或 registry。

**前置条件**：

- 账号有 `managementAdmin` 权限。
- 地址是不含内嵌凭据的 `http` / `https`；模型地址要指向模型自身的目录（权重文件所在的那一层）。
- 目标节点在线且 agent 版本足够新（否则报 `MODEL_SOURCE_REQUIRES_NEWER_AGENT`）；节点访问不到镜像站时，可用管理节点中转。

内网常有普通的 HTTP 文件服务器（Apache/nginx/Caddy 的 autoindex 列表页），模型目录和
`docker save` 归档直接躺在上面。这类地址既不是 Hugging Face / ModelScope 的 API，也不是
registry，本指南讲怎么把它们当成一等导入来源。

两种导入都需要 `managementAdmin` 权限。地址允许内网主机与明文 `http`，但必须是**不含内嵌凭据**的
`http`/`https`，重定向不超过 5 次，且模型目录的每次跳转都要留在注册时那个主机上。

## 从 HTTP 目录注册模型

模型页「注册模型」→ 来源选「HTTP 目录」→ 填目录地址 →「解析」。

目录地址要指向**模型自己那一层**（如 `https://hf-mirror.zstack.ai/Qwen/Qwen3-0.6B`），不是站根。
目录 URL 来源的模型只从它自己的目录下载，拉取设置里的站点规则不作用于它们，但下载会经节点的拉取代理：内网文件服务器要写进代理条目的 `no_proxy`，否则会被送到代理上（旧版本这类下载直连）。

解析读的是服务端的目录列表页，规则如下：

- 平台不要求目录布局：有 `config.json` 时据此读出架构、精度与上下文长度；没有（例如只有 GGUF 分片）也能登记，只是这些元数据为空，权重大小按目录里的 GGUF 文件计。目录一个文件都没有、或 `config.json` 解析失败时报 `HTTP_DIRECTORY_NOT_A_MODEL`。
- 列表页里的「目录大小」是给人看的两位有效数字（`1.4G`），只作参考。磁盘准入、进度与完整性校验都用
  下载响应实测的字节数，下载完成后节点写一份实测清单作为完成标记，二次对账不会重下。
- 目录地址会归一化：结尾斜杠、主机名大小写、显式端口指向同一个目录；粘贴的是文件地址时回退到它所在的
  目录。
- 列举是有上限的：最多 3 层子目录、合计 5000 个条目、单个列表页 8 MiB、单个列表页 30 秒超时。超出上限报
  `HTTP_DIRECTORY_TOO_LARGE`——截断的列举会静默注册出一个缺权重的模型，所以这里宁可报错。
- 连不上或读不出列表页报 `HTTP_DIRECTORY_UNREACHABLE`。

「目录 ID」默认取地址末两段，注册前可改。它决定部署时能否自动命中推理目录／模板的参数预设；目录里的模型
不在推理目录里同样可以注册，只是要手选参数。

注册完成后模型页的来源标为「HTTP 目录」，之后的下载与部署走和其他来源完全相同的获取方式（节点本地已有 / 同步组内复制 / 下载，见[配置镜像拉取](configure-pull-settings.md)）。目录源**没有 revision 概念**，不具备 Hugging Face / ModelScope 那样的 commit
可复现性，生产环境建议指向发布后不再覆盖的目录。

目标节点的 agent 过旧时，下载会被拒绝并报 `MODEL_SOURCE_REQUIRES_NEWER_AGENT`，升级 agent 后重试即可。

## 从 URL 导入镜像归档

镜像页「社区镜像」或「自定义镜像」标签 →「添加…镜像」抽屉里的「从 URL 导入」→ 粘贴 `docker save` 归档的地址 →「解析」。

解析做两件事：`HEAD` 拿「归档大小」；再用 `Range` 取归档尾部（必要时补取头部）扫 tar 头，把归档里
**真实的镜像引用**读出来。文件名与 tag 没有关系，不要靠文件名猜。然后：

- 归档里的引用与目录中某一行相同时，直接把 URL 追加到那一行的「获取地址」，并跳到该行；
- 都不相同时，用归档里的第一个引用预填新镜像表单，URL 预填进「获取地址」。

服务器不支持 `Range`、或归档被压缩过时，解析会提示「无法在下载前解析」。这不是错误：按提示自己填镜像引用，
节点在 load 之后会把归档实际携带的 tag 打上目录引用（见下节）。两种情况下都不需要用户改引用重试。

「获取地址」是镜像已有的字段，现在既放 registry 引用，也放归档 URL。归档 URL 只会被下载并 load，
**永远不会被当成 registry 引用去 pull**：节点下拉、拉取候选与拉取命令都按这条规则过滤。部署也不会自己选归档 URL 去下载：要用归档，先在镜像页的节点行导入，再部署。

## 节点获取方式：直连或管理节点中转

镜像详情页的节点表里，这一行的「获取方式」除了默认的「按拉取设置拉取」，还有两种 URL 相关的选择：**「从 URL 导入…」**（这次现填地址），
以及该镜像已经声明过的、按主机名命名的地址条目。两者点「获取」都会先打开弹窗，而不是直接开始下载：

1. 粘贴归档地址（选已声明的条目时会预填并自动解析一次）；
2. 点「解析」，服务端用 HEAD + Range 读出归档大小与**归档里真实的镜像引用**；
3. 核对引用与当前镜像是否一致——不一致会红字拦住，不允许开拉；
4. 需要的话勾上「管理节点中转」；
5. 点弹窗里的「拉取」开始下载。

弹窗里确认后，这个地址会被记录进该镜像的「获取地址」，于是其他节点的镜像页也能直接选它；这也是「拉取失败后
重试」仍然知道该去哪里下载的原因。

两种下载路径：

- **直连**：节点自己下载归档并 load。归档内带的 tag 与目录引用不一致时，节点会把目录引用补打上去，
  真实 tag 记进这一行的消息里，便于事后核对。
- **管理节点中转**：管理节点下载归档并流式推送给节点，服务端**不落盘**。节点访问不到镜像站、或只有
  管理节点能出网时用它。该传输不可续传，中断后重试从头开始，进度显示已传字节数。

归档读不出引用（被压缩过、或镜像站不支持 `Range`）时不会拦截，只给一条警告：这种归档没法在下载前核对，
节点会在 load 之后把归档实际携带的 tag 记进这一行的消息里。

导入完成后镜像在节点上是 `present`，部署时节点直接使用；实例始终以目录里的规范引用启动。

## 常见错误

| 错误码 | 含义与处理 |
|---|---|
| `HTTP_DIRECTORY_UNREACHABLE` | 目录列表页读不到：检查地址，并确认服务端会返回目录列表 |
| `HTTP_DIRECTORY_NOT_A_MODEL` | 目录里一个文件都没有，或 `config.json` 解析失败 |
| `HTTP_DIRECTORY_TOO_LARGE` | 文件数或层级超出上限，请指向模型自身的目录 |
| `MODEL_SOURCE_REQUIRES_NEWER_AGENT` | 目标节点 agent 过旧，先升级 agent |
| `IMAGE_ARCHIVE_URL_INVALID` | 归档地址不可用：必须是无内嵌凭据的 `http`/`https` |
| `IMAGE_ARCHIVE_URL_UNREACHABLE` | 归档读不到，检查地址与网络 |
| `IMAGE_ARCHIVE_URL_NOT_DECLARED` | 该 URL 不在这个镜像的「获取地址」里，先把它加进去再同步 |
