# 使用存储：本地目录、NFS 与 NFS 加本地缓存

模型文件放在**存储**里。一个存储有一种类型，决定权威的模型文件在哪、节点怎么读到它：

| 类型 | 模型文件在哪 | 节点怎么读 | 适合 |
|---|---|---|---|
| 本地存储 | 每个节点自己的目录 | 直接读，每节点各一份 | 节点数少，或要求不依赖网络存储 |
| NFS | NFS 导出，agent 负责挂载 | 挂载后直接读，所有节点共用一份 | 链路快、模型多而本地盘小 |
| NFS 加本地缓存 | NFS 导出 | 先拷到节点的缓存目录，再从缓存读 | 链路慢、长期服务、要求 NFS 掉线时不受影响 |
| 已挂好的共享目录 | 节点上已经挂好的目录（CephFS、Lustre、自己挂的 NFS） | 直接读，agent 不挂载 | agent 不是 root、或不是 NFS 的共享文件系统 |

新装的平台带一个名为 `default` 的本地存储，目录是 `/opt/gpuworks/models`，可以改名、改路径或删除。
存储的目录总是写在存储上，与 agent 装在哪、状态目录在哪无关：本地存储必须填目录，「NFS 加本地缓存」不填缓存目录时
用 `/opt/gpuworks/cache/<存储名>`。不以 root 运行的 agent 建不了 `/opt` 下的目录：它第一次接入时，平台在默认本地存储上
给这台节点记一个它自己能写的目录（agent 状态目录下的 `models`），在存储详情和编辑框里都看得到、改得了，之后不会被覆盖。
其他原因用不了某个目录时，节点列表会提示，编辑存储在「适用节点」里给它单独设目录即可（选「全部节点」时也可以给个别节点单独设）。
从旧版本升级时，各节点原来实际使用的目录会记成它们各自的单独设置，模型文件的位置不变。
设计取舍见 [ADR 0034](../adr/0034-model-files-belong-to-storages.md)。

## 添加一个 NFS 存储

1. 打开「存储」页，点「添加存储」，类型选「NFS」或「NFS 加本地缓存」。
2. 填导出地址（`主机:/路径`）。挂载点默认 `/mnt/gpuworks/<存储名>`，各节点一致；挂载选项默认 `rw,noatime`，
   其余交给内核协商，只接受白名单里的选项。
3. 选这个存储用在哪些节点：全部、按标签（新节点带上标签就自动挂载），或逐台（逐台时可以给某台单独设挂载点，
   或勾选「使用已有挂载」让 agent 不挂载也不卸载）。
4. 点「试挂」。平台在一台节点上临时挂载、读根目录、在 `.gpuworks/` 下试写一次，然后卸载。失败时直接给出原因：
   缺 NFS 客户端（装 `nfs-common` 或 `nfs-utils`）、服务器不可达、权限被拒、导出不存在。
5. 保存后 agent 在各节点上挂载，存储卡片显示「N/M 可用」和有问题的节点。

挂载需要 agent 以 root 运行。试挂能挂上但写不进去（例如 `root_squash`）时，存储以**只读（停用）**状态保存：
可以扫描导入和部署，不能往里下载或删除。

## 导入已有的模型库

NFS 上已经有按 `<组织>/<仓库名>/` 存放的模型时：

1. 在存储卡片上点「扫描导入」。一台挂载正常的节点遍历目录（默认最多 4 层），解析常见格式与清单，列出模型入口。找到一个模型后仍检查子目录，避免漏掉仓库中的其他入口。
2. 列表显示模型格式、任务类型、身份依据和异常原因。管线声明的 `audio_vae`、编码器等组件不会作为独立模型列出；适配器也不会当作基础模型。层级过深、元数据损坏、缓存布局等显示跳过原因，缺片显示未完成。
3. 勾选后「导入所选」。平台重新检查选中目录并匹配已有登记，否则新建。仓库内的独立子目录按本地模型及实际相对路径登记；这与远程下载时保留仓库层级的子目录制品不同，不会自动混绑。导入只写平台数据库，不往存储写任何文件。
4. 推理模板按模型身份匹配权重。被识别为模型入口只证明目录结构符合规则，不保证任意推理引擎都支持它。

识别覆盖 Transformers safetensors/bin（含索引分片）、Sentence Transformers、Diffusers 管线、ModelScope 标准配置与权重、Mistral 原生格式和 GGUF。ONNX 当前要求同目录 `config.json` 与 `model.onnx`；SavedModel 要求 `saved_model.pb` 和 `variables/variables.index`。
GGUF 会区分模型与 mmproj/controlvector 组件，并组合标准命名的分片。不同量化放在不同子目录时分别列出；同目录多个独立模型会提示分目录导入，不把它们合成一个模型。没有关联清单时，不自动推断根目录组件与量化入口的运行依赖。

新建模型的 API 能力来自结构化任务声明：`text-ranking` 对应 rerank，`feature-extraction`、`sentence-similarity` 对应 embeddings。模型卡支持单个任务或任务列表，ModelScope 的 `configuration.json` 和 Sentence Transformers 模块也提供任务证据。声明优先于底层架构，目录名称和说明正文不作为类型规则。
任务判断参考 AIOS 的来源顺序：模型卡明确声明优先，任务专用模块和模型卡标签优先于 ModelScope 的通用任务配置，底层架构只作兜底；同优先级的证据冲突时保留空能力并显示原因。未知类型不再默认 chat。本地目录注册使用同一个解析器；已存在模型保留其 API 能力，重扫、重导入和刷新不会自动改写旧记录。本期未增加人工覆盖识别规则的入口。

组合模型按组件的文件契约检查：Sentence Transformers 的 Transformer、Dense 检查配置与权重，Pooling、LogitScore 只检查配置，Normalize 不要求独立目录；Diffusers 的模型组件检查配置、权重及索引分片，scheduler 检查配置，常见 CLIP/T5 tokenizer 检查词表文件。未知自定义组件会提示“组件文件布局尚未验证”，不会仅因目录存在就标为完整。当前权重检查覆盖标准默认文件名与分片；需要额外 variant 参数的布局不自动推断。

单模型登记与扫描导入都会拒绝已确认的组件目录、多模型目录，以及文件缺失或无法验证的已识别入口。扫描导入还要求恰好识别出一个入口；显式登记未知布局保留原有兼容行为。

大型权重索引按块解析，只保留引用的分片路径；GGUF 可读取较大的 tokenizer 元数据。达到读取上限会提示识别未完成，不作为文件损坏或缺片的证据。

完整识别需要新版 agent；服务端连接旧 agent 时保留原有文本元数据读取兼容路径。

库有变化时再点一次扫描：新目录标「新发现」，已导入但不见了的目录对应的模型文件标为缺失，新的启动会被阻止并给出原因。

## 部署时选存储

部署表单的「模型权重」一栏列出存储选项（部署不选择从哪里获取，节点按[拉取设置](configure-pull-settings.md)自行决定）：

- **存储 X 上已有**：每个已经有这个模型、目标节点能访问的存储一项。本地存储那项就是原来的「本地已存在」。
  NFS 写「直接读」，NFS 加本地缓存写要先缓存多少；目标节点挂载不可用时这项置灰并写明原因。
- **保存到**：节点需要取模型时（同步组内复制，或下载）保存到哪个存储，预选默认存储；复制只保存到本地存储。

所选的存储只决定需要获取时保存到哪，部署不绑定存储。之后每台节点上的副本读它能读到的那份：

1. 节点自己盘上有（本地存储，或 NFS 加本地缓存已缓存的），就用它；
2. 否则节点挂载的 NFS 上有，就直接读；
3. 否则 NFS 加本地缓存的存储里有，先复制进这台节点的缓存；
4. 都没有才获取（同步组内复制，不行再下载），保存到部署时选的存储——它适用于这台节点时；否则保存到默认存储，再否则其他启用的本地存储。

平台不会自动往 NFS 里下载。部署时选了"保存到"某个 NFS，而它里面没有这个模型（下载失败或被删了），副本会停下并说明原因，
不会改成在各节点各下一份。

要让部署只读某个存储（比如只想从 NFS 读），在部署的节点条件里加"存储: 名称"。不在该存储适用范围内的节点不会被选中；
在范围内但这会儿挂载不可用的节点仍是候选，放置原因里会写明。

部署详情里每个实例都显示它读的模型文件：在哪个存储、宿主机上的路径。只有一个本地存储时，表单与以前完全一样。

## 缓存准备进度与恢复

NFS 加本地缓存的模型在本地副本完成前不会启动实例。部署列表显示当前准备摘要；详情按实际节点、主模型与组件、所选存储展示检查源、复制、校验、安装和缓存淘汰阶段。单个权重文件未完成时也会更新已复制字节；总量未知时不显示百分比，速率连续稳定后才显示预计剩余时间。

部署填充缓存不限速。模型页手动复制可以为这一次复制设限速（MiB/s），留空或 0 即不限；重试失败的复制沿用它的限速，之后的新复制不继承。

连续两分钟没有实际进展会提示复制无进展；主动限速等待不算阻塞。该提示与存储健康检查报告的“NFS 无响应”、节点离线、磁盘不足分别显示。观测超过 15 秒未更新、节点断开或 server 重启后会回到等待更新，不沿用陈旧速率。

滚动升级时先升级 server，再升级 agent：高频观测不逐帧写库由新版控制面实现；完整阶段、阻塞占位和安全停止确认需要新版 agent。

失败的缓存复制可以在详情中重试。平台先检查容量并确认旧任务退出，再创建新复制意图；仍阻塞在文件系统里的任务不会因点击重试而产生第二个 writer。部分文件仅在源清单的路径、大小与修改时间一致时续传；这不是全文件校验和保证。

停止部署会撤销它的缓存准备引用；其他部署仍需要的复制继续进行。最后一个引用撤销后取消该缓存复制，保留部分文件；阻塞中的 I/O 退出前继续占有任务槽。已完成的缓存保留供后续使用。旧 agent 缺少阶段观测时显示等待更新，不据此判定 NFS 故障。

## 本地缓存的容量

「NFS 加本地缓存」的存储有一个缓存上限（每台节点，可按节点覆盖，默认不限），平台还为缓存盘保留一部分空闲空间
（「存储」页设置，默认取磁盘 10% 与 50 GiB 中较小的一个）。往某台节点缓存新模型而空间或上限不够时，平台按最近使用时间
从旧到新淘汰缓存，只淘汰没有部署或实例在用、不在拷贝中、NFS 上还有权威文件的那些；单个模型比缓存上限还大时直接拒绝并说明，
不会悄悄改成从 NFS 直接读。磁盘够、但上限被在用的模型占满时，部署事件写明「缓存已被在用模型占满」，调高上限或停掉用这些模型的部署即可。存储卡片上的「清理缓存」手动淘汰所有可淘汰的缓存。


### 默认策略与节点例外

创建「NFS 加本地缓存」依次填写基本信息、节点范围、缓存策略和确认信息。在节点范围内，可为每台节点选择「跟随默认」「自定义上限」或「不限」。自定义支持 GiB/TiB；不限表示没有逻辑上限，磁盘保留空间仍生效。上限不是磁盘独占预留，也不是集群总配额。

存储详情的「节点」页展示默认目录、默认上限和每台节点的有效配置。修改默认上限只影响跟随默认的节点；单节点设置可独立修改目录或上限。恢复上限继承不会顺带重置目录。按名称、地址、配置来源和整理状态筛选后，可跨页选择固定节点集合进行批量设置；保存只修改明确选择的字段。

节点范围与配置例外分开：给标签范围中的节点设置例外不会将其永久加入范围。节点失去标签后，例外保留为「未适用」，重新匹配时继续生效。历史显式选中的节点仍是范围成员。修改范围时，请检查已有混合标签与节点选择。

降低上限前可查看已缓存、可回收和受保护数据。保存后系统在后台整理，只回收安全副本；受保护数据包括正在使用、正在传输或缺少权威副本的数据。即使部分数据暂时不可删除，也会先回收安全部分，并显示待处理、整理中、受阻或失败等状态。离线节点等待恢复，失败可重试。「清理缓存」会清理选中节点的可回收数据，不保证清空受保护数据。

缓存删除超时或失败后，模型文件保留为「删除待确认」，不会继续用于部署或重新复制。点击整理/清理重试会沿用原删除标识，先确认这次删除，再按最新容量重新规划。确认前，删除模型、节点、存储或改变相关目录/作用域会被拒绝；调高缓存上限仍可保存。

此删除协议需要同步升级节点 agent；旧 agent 不支持时会返回错误并保留待确认记录。agent 把待删除目录原子隔离，并在自身状态目录的 `.gpuworks-evictions/` 保留小型回执，避免断线、重启或迟到重试删除后来填充的模型。回执须随 agent 状态保留，不应作为普通缓存清理；文件系统不支持目录同步或状态目录不可写时，操作会安全失败。

变更目录不会搬迁旧文件；旧目录里的文件不计入新目录的缓存预算，也不会被新目录的后台整理删除。新目录尚未上报容量、节点离线或统计缺失时，容量影响显示未知。详情刷新失败会保留已有数据并提示可能过期，可点击重试。编辑中的草稿不会随轮询变化。若其他管理员已修改配置，全量范围编辑会提示冲突；重新打开后基于最新配置修改。

## 多套 gpuworks 共用一个 NFS

每套 gpuworks 各自添加存储、各自扫描导入，互不影响。可写的存储上，每套控制面在 `.gpuworks/control-planes/` 下写一个心跳文件，
存储卡片显示「还有哪几套 gpuworks 在用」。删除共享存储上的模型文件时，如果别的 gpuworks 5 分钟内出现过（各自每分钟刷新一次心跳），平台提醒并要求勾选
「强制删除」。心跳只是提醒，不是锁：被强制删除后，别的控制面再次扫描会把它标为缺失，正在从 NFS 直接读的实例重启时会失败。
约定一个库只有一套 gpuworks 往里写，其余只读或用「NFS 加本地缓存」。

## 浏览存储里的文件

管理员可以在存储详情里浏览整个存储，下载任意文件或目录，并在两个区域里放文件（[ADR 0053](../adr/0053-storage-files.md)）：

- **可写区域只有两个**：`files/`（通用区，离线数据集、tokenizer、prompt 集之类放这里）和 `.gpuworks/apps/`（应用的数据目录）。
  上传、新建目录、改名、删除只能在这两个目录之下进行，`files` 与 `.gpuworks/apps` 本身不能删除或改名；它们不存在时第一次写入会自动创建。
  模型文件目录和 `.gpuworks/` 的其余部分只读，模型文件仍只由模型管理改动。存储停用时整个存储只读，但仍可浏览和下载。
- **节点**：本地存储在每台节点上是各自的目录，先选节点再浏览；共享存储（NFS、NFS 加本地缓存、共享目录）由平台挑一台在线、
  已就绪、数据通道已连接的节点代办。NFS 加本地缓存浏览的是 NFS 本身，不是节点缓存。节点上的 agent 需要升级到支持存储文件的版本。
- **上传**：一个文件一次请求，浏览器边读边传，平台不落盘。可选「上传后解压」（tar、tar.gz、zip）：拒绝绝对路径、`..`、
  符号链接、硬链接与设备文件，解压后的总大小与条目数有上限。文件先写到 `.gpuworks/incoming/` 下的暂存位置，完整收到（并解压完）后才原子改名到目标，
  中途失败或取消不会在目标处留下半个文件。**不支持分块续传**：中断后要重新上传整个文件。
- **经 Cloudflare 等反向代理传大文件不支持**：这类代理对请求体大小有上限（Cloudflare 免费与 Pro 套餐为 100 MB），超过时上传会被代理直接拒绝。
  需要上传大文件时直连 gpuworks 的地址，或先把文件放到节点上再从那里拷进存储。
- **下载**：文件原样下载；目录边打包边传，默认 `.zip`，可选 `.tar.gz`，包内以目录名为顶层目录。符号链接不跟随：被跳过的链接列在包内
  `SKIPPED_SYMLINKS.txt` 里。目录下载事先不知道总大小，浏览器只显示已下载量；中途出错时浏览器只显示「下载失败」。
- **删除**先把文件移进存储的回收目录，字节在后台删除，与删除模型文件相同。

## 停用

任何存储都可以停用。停用表示只读：不再下载、复制进来或删除模型文件（部署触发的下载同样被挡），已有的模型文件照常可以部署。
镜像不在存储里（它们在各节点的容器运行时里），停用存储不影响镜像同步。

## 注意

- **NFS 掉线**：hard 挂载下，已经加载完权重的实例通常能继续服务；重启、L2 唤醒要重新读权重，会卡住或失败。
  需要不依赖 NFS 的部署请用「NFS 加本地缓存」。
- **启动前检查**：agent 创建容器前会检查模型目录是否存在（2 秒时限），不存在就以 `MODEL_PATH_UNAVAILABLE` 失败，
  不会让引擎在空目录上启动。
- **节点模型根目录**已并入本地存储：要换盘，给本地存储改路径或添加一个新的本地存储，不再在节点上单独设置。
