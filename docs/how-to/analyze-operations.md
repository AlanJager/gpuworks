# 查看运营分析

**适用场景**：对外提供推理服务时，按 API key 核对任意时间段用了多少 token、缓存命中多少；看各部署这个月的成功率与首 token 延迟；找长期闲置的卡；看每个部署占了多少卡时、每百万 token 用了多少卡时。

**前置条件**：server 升级到带运营分析的版本。统计从升级那一刻开始实时累加；升级前的 Token 用量与服务质量会从逐请求记录（默认保留 7 天）补算一次，GPU 利用与卡时不补算。设计依据见 [ADR 0055](../adr/0055-long-term-statistics.md)。

## 1. 打开页面

控制台侧边栏「概览」组里的「运营分析」。顶部选时间段（今天、昨天、近 7 天、近 30 天、本月、上月，或自选）和粒度（按小时、按天）；按小时最多看 7 天，且只到按小时数据的保留期为止（默认 31 天），更早的只有按天数据。天的边界按「统计时区」计（设置 › 数据保留，默认 server 所在时区）。

四个标签：

- **Token 用量**：每个 API key 在每个部署上的请求数、总输入、其中缓存命中、未命中输入、输出（其中思考）。命中率只算报了缓存命中的请求：SGLang 的 Anthropic `/v1/messages` 接口不报缓存，这类请求的输入计入总输入、不计入命中率的分母。没拿到 usage 的请求（报错、客户端中途断开）单独计数，token 不计入。可以按 key、部署、模型分组，表格可导出 CSV。已吊销的 key 仍然显示名字并标「已吊销」；吊销功能上线前就被删掉的 key 显示编号。
- **服务质量**：各部署的请求结果（正常完成、长度截断、客户端退出、连接中断、出错）、首 token 与端到端时间的 P50/P95、输出速度。分位数由分档计数还原，误差约 10%。
- **GPU 利用**：利用率、显存、功耗、温度的均值与峰值；热力图可以按卡型、节点或单卡分行，在利用率、功耗、温度、显存之间切换。可以按节点标签（书写标签与系统标签，同一个键的多个值任一满足、不同键都要满足）和卡型筛选；节点标签按节点现在的标签匹配，已删除的节点不会出现在按标签筛选的结果里。筛选覆盖不超过 256 张卡时逐卡列出（包括「长期闲置卡数」）；超过时按卡型或节点汇总列出，闲置卡数不统计，按单卡看需要先筛选。按节点看超过 100 个节点时，热力图只显示所选指标最高与最低的各 50 个节点，明细表仍列出全部节点。
- **卡时**：每个部署占用的卡数 × 小时（dGPU 按分到的显存份额折算），平均与最大副本数，以及同一时段的 token 数算出的「每百万输出 token 卡时」。卡时不涉及价格。

升级前补算出来的时间段在图上用浅色背景标出：补算来自逐请求记录，流量大时那段记录是抽样的（按权重估算），而且当时网关还不认识 `/v1/messages`、`/v1/responses` 的 usage，这些请求没有 token。

## 2. 在 API 令牌页看每个 key 的用量

API 令牌页的列表有「今日 token」和「近 7 天 token」两列，点数字跳到运营分析里这个 key 的明细。

## 3. 调整保存多久

设置 › 数据保留：Token 用量与其余统计分别设置按小时、按天保留多久（默认 31 天、400 天），三类统计可以分别关闭。改短后，超出的部分在后台分批删除。各项的当前占用也在这一页。接口见 [API 参考](../reference/api.md#analytics运营分析)。
