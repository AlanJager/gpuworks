# v26.11.2

发布日期：2026-11-08 · 发布线：26.11 · 提交：`3cf500e60`

这一版重点改善离线与内网环境下的易用性，并修复推理模型的 Playground 显示与压测指标、agent 连接配置和 API Key 吊销等问题。
建议所有 26.11 用户升级，尤其是在内网或离线环境部署的用户。本版没有数据库迁移。

## 升级须知

- **内网来源默认放行**：管理节点访问普通内网与本机回环地址的 HTTP 来源，从默认拒绝改为默认放行。
  需要保留旧行为时，升级前在 `server.yaml` 写入 `outbound_restrict_private_hosts: true`，已有的 `outbound_allow_private_hosts` 继续生效。
  元数据、链路本地与特殊保留地址在两种模式下都始终拒绝。
- **存储路径**：`storage_probe_roots` 不再限制新建和修改存储的路径，只用于启动时对已有存储的告警。
- **先升级 server，再升级 agent**：压测指标修正（agent 发压时）、Docker 启动等待和 `runveil load` 都在 agent 一侧，需要 agent 也升级到 v26.11.2。

## 新增

- `gpuworks-agent runveil load -i FILE REF`：把 `docker save` 或 OCI 归档（`.tar` / `.tar.gz`）导入 runveil（udocker）节点，
  不需要管理节点能访问 HTTP 来源，也不需要停 agent。见[离线环境部署](../how-to/deploy-offline.md)。
- `server.yaml` 新增 `outbound_restrict_private_hosts`（默认 `false`），开启后只放行 `outbound_allow_private_hosts` 授权的内网目标。
- `server.yaml` 新增 `storage_denied_paths`：整体替换存储禁用目录的内置清单，`[]` 表示不禁用任何目录。见[配置与环境变量](../reference/configuration.md)。
- 压测报告新增“首个可见回答”时间与“有输出但没有回答文本”的请求数；流式请求的 usage 里有输出 token、却没有可识别文本时，
  给出告警 `BENCHMARK_STREAM_OUTPUT_UNRECOGNIZED`。见[运行评测并解读报告](../how-to/benchmark.md)。

## 变更

- 存储路径不再要求位于 `storage_probe_roots`（默认 `/opt/gpuworks/models`、`/opt/gpuworks/cache`、`/mnt/gpuworks`）之下，
  `/data/models` 这类路径可以直接使用；系统目录仍然禁止。
- `outbound_allow_private_hosts` 与 `outbound_restrict_private_hosts` 保存后，下一次管理节点出站请求即生效，不再需要重启 server。
- 出站策略拒绝的来源报 `IMAGE_ARCHIVE_URL_POLICY_DENIED`，不再误报为“无法访问”。
- agent 启动时 Docker 守护进程尚未就绪，最多等待 2 分钟；仍未就绪时以 `daemon_not_ready` 为原因临时改用 runveil，
  Docker 就绪后自动切回。新生成的 systemd 单元排在 `docker.service` 与 `containerd.service` 之后启动。

## 修复

- 从节点本地目录注册的模型，配上声明了 Hugging Face / ModelScope 等公共权重来源的推理模板时，部署表单反复报来源冲突、无法部署。（GWKS-216）
- 平台下载取消后留下的 `x.part` / `x.part.state`，在 `x` 已由其他工具下完时仍被判为“未完成下载”，模型无法注册或扫描。
- nohup 方式安装或重启 agent 时，继承 shell 里旧的 `GPUWORKS_CONNECT_MODE`、`GPUWORKS_SERVER`、`GPUWORKS_TOKEN` 等环境变量，
  把已写入配置的连接方式改回旧值。
- agent 先于 Docker 启动时永久改用 runveil，多机部署因 runveil 不能暴露 RDMA 设备而被拒。
- vLLM 新版本把思考内容放在 `delta.reasoning`（26.11 自带的 `cuda12.9-vllm0.31.0-r2` runner 即如此），Playground 与 AI 助手不显示推理过程。
  现在同时识别 `reasoning_content`、`reasoning` 与 `thinking`。
- 压测负载生成器不识别 `delta.reasoning`：TTFT 包含了整段思考时间，TPOT 被低估，思考就用完输出预算的请求被排除在 TTFT/TPOT 样本之外。

## 安全

- 吊销不存在的 API Key 前缀返回 404 `API_KEY_NOT_FOUND`，不再误报“已吊销”；吊销前已在进行的认证不会放行吊销后的新请求。（GWKS-203）
- `klauspost/compress` 升级到 1.20.2，修复 GO-2026-6865；该库用于解压导入的 OCI 镜像层和下载的安装包。（GWKS-214）
- 使用 Go 1.26.10 构建，修复 `crypto/x509` 的 GO-2026-6809，该代码路径经 server_dial 可达。
