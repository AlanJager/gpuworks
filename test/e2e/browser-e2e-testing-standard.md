# GPUWorks 浏览器 E2E 测试规范

本规范适用于 `test/e2e/` 的真实浏览器测试，以及新增的控制台业务验收。目标是证明用户通过
GPUWorks 完成的操作在控制面、agent 和适用的运行时中生效。页面加载、成功提示、HTTP 200、
数据库有一行、实例标记 `running`，均不能单独证明完整业务成功。

本规范展开根目录 [开发规约](../../CLAUDE.md) 的浏览器测试要求；测试层级以
[CONTEXT.md](../../CONTEXT.md) 和 [测试指南](../../docs/dev/testing.md) 为准。新增与修改的用例必须遵守本规范；
既有用例按实际证据登记缺口，不能因历史存在而自动视为合格。

## 证据链与适用边界

每个业务用例必须先声明它要证明的层次：

| 证据层 | 必须证明 | 不足以证明的替代物 |
|---|---|---|
| 界面 | 用户可达的入口、正确字段与校验、加载和错误恢复 | 仅打开页面或出现 toast |
| 请求 | 实际请求的 method、path、query、body、响应状态与合同 | 只监听到一次请求或收到 2xx |
| 持久化 | 独立 GET 与刷新/重进后的值、绑定、期望状态一致 | 前端本地 state、提交响应原样回显 |
| 调和与执行 | 控制器调度结果、实例观测状态、agent 收到的 workload 与实际执行结果对应 | 只检查 deployment 的 desired state |
| 运行时 | 容器、文件、网络或真实推理请求产生预期效果 | recording driver 的成功返回、fake GPU 名称 |

只读列表使用请求和权威数据结果证明正确性，不要求制造 mutation。Playground 对话的持久化
主体是本浏览器 IndexedDB，必须验证刷新、账号隔离与清理，不能要求不存在的服务器对话表。
纯界面偏好按产品规定的 URL、浏览器存储或组件状态验证。标记不适用必须说明业务原因。

业务闭环必须使用真实 server、真实管理路由和落盘 SQLite 数据库。
数据面分别验证公开 `/v1/*` 和实际使用的 `/api/v1/playground/v1/*`，不能用一侧代替另一侧。

## 先核对产品合同

编写定位器与 expected value 前，按以下顺序核对目标流程：

1. [领域词汇](../../CONTEXT.md)、[用户术语](../../docs/reference/glossary.md)、[页面导览](../../docs/reference/web-ui-tour.md)
   与相关 ADR，确定节点/部署/实例、模型/权重/档位、就位/获取、期望/观测状态的区别。
2. [API 约定](../../docs/reference/api-conventions.md)、[路由清单](../../docs/reference/api.md)、实际 DTO、路由与
   后端校验，确定字段、单位、默认值、合法范围、错误码和权限。文档与实现冲突必须登记并解决，
   不能任选一方制造绿灯。
3. [主题 token](../../ui/src/theme/tokens.ts)、全局样式、Ant Design 主题配置、现有共享组件、
   页面实际组合及 [i18n 约定](../../ui/i18n/README.md)，确定文案、交互和样式来源。
4. 发现概念、组件或合同漂移时，先登记产品 blocker，补产品回归测试并修复实现，再恢复 E2E。
   通过类型检查、相关单元/集成测试与真实浏览器交互后，才固化新合同。

关联已有节点、模型、存储、镜像或模板应通过产品的资源选择器，不得用输入内部 ID 绕过选择流程。
引擎名、参数、GPU 厂商能力和兼容性来自服务端字典与事实，测试不得另建一套猜测规则。
GB/GiB、bytes、显存比例、核心份额、token/s、请求数和毫秒必须按各字段合同区分；未知值不能写成 0。

禁止放宽断言、补备用 locator、注入 DOM/CSS、跳过字段或提高 retry 来适配产品缺陷。
合法的入口变更应同步更新用例，例如行操作迁入菜单后，应真实打开菜单并选择菜单项。
被正式退役的入口删除其 UI case，保留退役 ID；仍有调用方的旧 API 归入兼容测试。

## 浏览器测试与 L1 至 L4

浏览器是一种驱动方式，不是新的 L 层级。报告同时声明浏览器范围和运行环境，不能把使用 Chrome
等同于 L4，也不能把所有 Go L2/L3 测试称为浏览器测试。

| 浏览器范围 | 环境与允许替身 | 可以证明 | 必须保留的限制 |
|---|---|---|---|
| 安装与页面冒烟 | 构建后的 server、内嵌 UI、独立 SQLite、真实 Chrome | 认证、页面、主要查询与入口可用 | 空库页面加载不能证明业务闭环 |
| 本地控制面闭环 | 真实 server/agent/WS、SQLite；可注入 GPU facts、recording runtime、外部服务 fixture | 创建/编辑/删除、评估、调度、workload 下发与回读 | 不证明容器启动、GPU 限额、推理成功 |
| 容器与数据面闭环 | 隔离的真实 Docker/udocker/nerdctl、fake-engine/tiny model、真实网关 | 容器生命周期、文件挂载、代理、流式、取消、sleep/wake 协议 | 不证明真实 GPU 性能、显存释放或厂商驱动 |
| 真机与外部兼容 | 显式 L4 资源池/云账号、真实驱动与引擎 | GPU 探测、dGPU、显存、跨机通信、真实推理/下载 | 按厂商、runtime、拓扑分别报告 |

外部模型仓库、Registry、云 provider、OpenAI 兼容引擎、AI 助手上游使用本地可审计 fixture，
必须忠实实现所测请求、默认值、错误、流式、usage 和取消行为。不得全部方法无条件返回成功。
带工具/函数调用的 fixture 必须让最终回答由本次工具结果决定，或按合同返回工具错误；固定成功
文案、忽略工具参数或结果的回答属于无条件成功。用例还要独立读取工具事实的权威来源，与工具
结果和页面渲染三方比对，不能只相信 fixture 的最终文本。
多轮或工具协议还必须校验会话结构本身：前置 assistant `tool_calls` 的调用 ID、名称、顺序、参数
与后续 tool 应答的 `call_id` 一一对应，不能只看最后一条消息的形状。缺少前置调用、错序、重复
或错误关联时，fixture 必须返回协议错误，不能生成成功事实答案；这些负例同时进入 fixture 自测。
mock 只能落在已声明的外部边界；控制面、数据库、调度与需要验证的 agent 路径不得替换。

禁止 `page.route()` / `context.route()` 的 `fulfill`、`abort` 伪造管理 API 成败或返回业务数据。
`continue` 只可作为有明确释放条件的并发 barrier，不修改响应。RTL 中的 API stub 不构成 E2E 证据。

控制面负例优先通过真实非法输入、权限、引用关系、并发操作、受控进程/依赖故障触发。
需要精确注入失败时，必须先实现并验证只在隔离测试环境启用的服务端 fixture，限定主体、runId、
次数和 method/path，失败请求与应用记录可关联，未知目标拒绝；生产默认不能暴露该能力。
当前没有通用浏览器故障注入 middleware、nonce catalog 或故障标记响应头，不能假定已存在。
无法安全构造的负例登记 `BLOCKED`，不得退回浏览器 mock。

## 环境门禁与确定性数据

每次运行必须有唯一 `runId`、源码 SHA、构建 SHA、浏览器版本、locale、时区、fixture 版本和环境 lane。
运行前至少检查：

- server `/healthz`、数据库迁移与登录可用，内嵌 UI 与 server 来自同一构建；401 不能当静态页加载失败。
- 所需 agent 在线，版本/架构、GPU/vendor/runtime/capability 与 lane 声明匹配；预置模型、镜像 digest
  和引擎健康真实可读。声明无 GPU 的用例不要求伪造真机能力。
- provider/engine fixture 的 runner 控制地址、server/agent 可访问地址分别可达，执行边界一致。
  远端禁止默认使用 runner 的 `127.0.0.1`；回环测试显式配置代理绕过，避免本地请求误走外部代理。
- 容器环境与已有 agent 隔离；不得在纳管在线工作负载的同一 daemon 上直接跑 L3。
  agent 的孤儿清理可能影响其它 workload；应使用专用宿主/daemon，而不是关闭清理来掩盖缺陷。
- L4 先核实资源归属、空闲 GPU、驱动、端口、网络与缓存；云资源必须可按 runId 回收。

门禁失败标为 `BLOCKED_INFRA`，不伪装产品失败或通过。门禁通过后发生的产品断线、错误状态或
恢复失败按业务断言判定，不能统一归为环境抖动。

资源名称使用 `e2e-{runId}-`；fixture 记录全部 ID、进程、容器、文件和临时转发的所有权。
所有权必须在资源创建后立即登记（句柄与凭证一起登记），不能等 fixture 全部创建成功后才登记；
准备阶段任一步失败都必须走同一回收路径，凭证取得后立即登记供脱敏与产物扫描，避免失败报告
泄漏未登记的秘密。不得依赖已有模型名称、固定目录条目数量、历史日志或列表第一行。需要目录的用例
导入自己的最小包；内置目录兼容用例另行锁定包 digest。前置可用 API 或受控 store fixture，被测操作
必须通过 UI。禁止靠直接改库完成被测 mutation，或让运行时事实仅来自人工插入的成功记录。

本地端口依次分配 8800、8802、8804 等，并记录实际地址；本地测试密码按项目约定使用 `password`。
每组独立数据库、agent state、模型/镜像目录、浏览器 context；互不依赖执行顺序。
全局设置、监听变更、升级与重启用例使用独立进程环境，不在共享 server 上并行。
时间基准取服务端/fixture 固定 UTC `T0`；精确边界使用实际存储精度，不靠执行速度碰运气。

失败先保存证据并冻结本次现场，避免重试或 teardown 抹掉根因。保留凭证的数据库、trace、
agent state 只放受控且 gitignored 的目录。清理按依赖逆序，仅删除本次 runId 的资源；保留现场
必须写明路径、负责人/回收入口和有效期，不能遗忘后台进程或付费实例。

清理成功是 PASS 的必要条件，必须来自实际观察，而不是“调用过清理函数”。自有进程确认退出，
runId 资源由独立 GET/列表证明不存在或已恢复。清理调用不得用 `ignore_errors`、空 `except`、
`|| true` 或只检查启动成功来吞掉失败；清理失败或残留必须使本次运行非 PASS，并在报告中列出
残留资源、所有权和回收入口。所有权字段只能在独立回读确认资源消失后清空；清理调用失败、超时
或回读不可用时必须保留 ID/名称和最后观测状态，写入 `remaining_resources`（含 scoped 回收入口）
与分阶段清理结果，不能因为调用过清理函数就把所有权清空成“已回收”。外部查询只有明确的“不存在”
才能当作已清理：`docker inspect`、
`kubectl`、API 等仅接受显式、大小写不敏感的 not found/no such；连接失败、权限错误、daemon
不可达必须判失败并记录 stderr，不能让查询错误满足清理断言；两类结果都要有 fixture 自测。

## 共享组件合同

各类组件的逐项编号要求见[组件检查清单](browser-e2e-component-checklists.md)，覆盖表单整体、
输入控件、选择器、表格、弹层、图表、日志、终端、Playground 等。下表用于定位范围，
编写和评审用例时须按检查清单逐项登记证据或缺口。

共享组件的 RTL 测试负责组合与状态穷举；浏览器仍须证明真实布局、焦点、请求和页面接线。
共享合同不替代每个消费页面的独立请求字段、权限和持久化证据。

| 组件或形态 | 必测维度 |
|---|---|
| `ResourceTable` 与分页列表 | loading/empty/error/data；搜索、排序、筛选、分页、行选择、操作菜单；长列表操作打开在当前视口；刷新保留合同 |
| 节点/模型/档位/镜像/存储选择器 | 可读名称、服务端搜索、无结果、候选禁用原因、选中项回填、换选/移除、过滤后名称保留、失效目标；大集合可找到目标 |
| `TimeRangePicker` 与监控时间上下文 | 每个可见 preset、custom 确认/取消、live/follow、URL、时区、精度、retention、请求与数据结果 |
| Text/Textarea/Number/Slider | 空与空白、默认值、长度/数值边界、单位、step、trim、0/负数/小数、非法输入、错误定位；精确 JSON 类型 |
| Select/Radio/Segmented | 每项真实选择、默认项、切回、禁用、条件字段显隐；每项精确提交值与回读，不能只打开下拉 |
| Checkbox/Switch/三态参数 | 默认、开关双向、禁用、未设置/显式 true/显式 false；省略、null、空值、0 不混用 |
| Secret/Password/一次性令牌 | 必填/选填合同、掩码、编辑留空语义、创建仅展示一次、刷新不回显、撤销与真实调用、产物脱敏 |
| YAML/JSON/命令编辑器 | 语法和 schema 错误、未知字段、表单切换不丢值、格式化不改语义、只读/克隆边界、可访问错误位置 |
| 上传/导入/下载进度 | 类型/大小/空文件/损坏/重复、部分传输、失败/取消/重试、最终内容或 hash 回读、关闭弹窗不假定任务取消 |
| Dialog/Drawer/Popover/Menu | 名称和角色、默认焦点、Tab/Esc、关闭后焦点返回、视口、嵌套 portal、提交中与防重复提交 |
| 图表/指标卡/时间线 | 查询和范围、已知样本、单位、聚合、缺失/零值/陈旧值区别、过滤联动；canvas 截图不能代替数据断言 |
| 日志流/Web 终端 | 连接、分块、过滤、取消、重连、关闭释放、鉴权、限额与空闲；xterm 输入输出须观察真实会话 |
| Playground renderer/Markdown/HTML 预览 | 各操作输入输出、SSE、附件、媒体生命周期、取消、复制；不可信输出与 sandbox/CSP 边界 |

组件来源包括 [ResourceTable](../../ui/src/components/resourceTable/ResourceTable.tsx)、
[TimeRangePicker](../../ui/src/components/TimeRangePicker.tsx)、
[监控时间上下文](../../ui/src/pages/monitor/TimeRangeContext.tsx)、
[NodePicker](../../ui/src/nodes/NodePicker.tsx)。以本次构建实际可见选项及后端合同为准。
例如 NodePicker 当前是搜索返回单页候选，应证明第 51 条可通过搜索找到，而不是断言不存在的下一页按钮。

共享表格还必须覆盖列宽拖动、列显隐/排序/重置及刷新回读；按 `tableId` 验证偏好隔离，
验证旧版未知列安全兼容、最小列宽以及名称/操作固定列不可隐藏或移动。
这些是浏览器本地偏好，不要求写入控制面数据库。

### 实际控件盘点与覆盖边界

新增或扩展页面 case 前，逐个盘点实际可达控件，包括快捷标签/chip、预设按钮、搜索框、
下拉框和条件显示的控件；不能只盘点表单字段或已写过定位器的部分。每个控件分别登记稳定 ID、
用户操作、请求字段或表达式转换、依赖控件、结果来源，以及对应 case 或明确缺口。
文案相近不代表同一合同：日志 `level=warn` 下拉筛选与 `WARNING` 快捷标签分别改变级别参数和
全文查询；镜像类型筛选与选择镜像后参数预填也必须分别登记，不能互相代替。

先列出完整适用范围，再登记已执行子集。缺控件、缺组合、缺数据或未运行时保留缺口；
单条 case 的 PASS 只适用于其实际断言，不得扩称为“页面筛选已覆盖”或“组件全覆盖”。
评审须把覆盖清单与页面实际控件、请求构造路径对照，不能只核对已有脚本是否全部通过。
该要求当前由盘点和评审执行，不代表已经存在自动发现控件的 Registry 门禁。

## 列表矩阵与数据量

每个列表分别登记以下维度，无能力的项目写 `N/A` 与业务原因。表格、卡片、目录选择器都适用，
但必须区分服务端分页、客户端分页和游标读取，不得强制所有接口使用同一种 envelope。

| 维度 | 强制场景与证据 |
|---|---|
| 初始加载 | 默认排序/分页/范围；行集合、总数、loading、空态、失败与重试 |
| 搜索 | 全值/部分值/大小写与空白合同/特殊字符/不存在/清空；query 与命中、排除集合 |
| 单项与组合筛选 | 每项可见枚举；至少两个条件各自有结果但交集为空；清空后恢复；不存在/失效资源 |
| 分组与汇总 | 支持分组时准备 A 两条/B 一条，验证数量、组内合计和切换不残留；明确汇总受不受筛选影响 |
| 排序 | 每列升降序、相等值的稳定顺序；验证全局排序再分页，不是仅对当前页排序 |
| 分页 | 每个真实 page-size、边界禁用、逐页 ID 无重复遗漏、返回顺序、过滤后合法页、末页删最后一条 |
| 刷新与轮询 | 修改后刷新、事件触发回读、失败恢复；后台轮询不得覆盖未保存表单或恢复已取消操作 |
| 时间 | 每个 preset 与 custom 的选中态、精确参数、响应、数据集合及边界 |
| 导出 | 真实下载字节、格式/schema、列与单位、记录数与过滤一致；空结果、失败及权限；仅支持时适用 |

**10、30、100 表示总记录数，不是 page-size。** 10 条验证字段与行操作；30 条验证真实跨页/滚动
和跨页操作；100 条验证多页/虚拟化、搜索、详情、编辑、删除、重复遗漏及溢出。节点/GPU 场景
可以在声明为模拟事实的 lane 中构造这些记录，不要求租 100 台真机。
当前共享表格每页选项为 10/20/50/100，页面可有独立配置；禁止为测试改变产品选项。
无法安全构造规定数据量时登记 `MISSING` 或 `BLOCKED`，不能用历史数据或选择 page-size 充数。

节点筛选需分别验证同 key 多值为“或”、不同 key 为“且”、状态多选及关键字的组合；用户标签和
`gpuworks.ai/` 系统标签不可混写。全体 facets/summary 与筛选后的 total 必须按各接口含义断言，
不能一律要求相等。模型 presence 的来源/存储/节点副本也不能合计成不同模型数。

### 组合查询必须证明真实语义

共享查询表达式、筛选状态或参数预填的控件必须登记组合关系和 AND/OR、优先级、重置与覆盖规则。
每项独立通过不能代表组合通过；任意两个简单下拉框的交集，也不能代替文本与快捷标签等不同构造路径。
至少覆盖每条相互影响路径及已知缺陷组合，其余组合显式登记缺口，不宣称已穷举全部排列。

- 用可归属的真实数据准备“同时满足 A/B”“仅满足 A”“仅满足 B”“均不满足”的可区分记录。
  分别验证单项、交集非空、各项单独非空但交集为空；按合同验证 OR 扩展与 AND 收窄，
  不能让全部 fixture 都满足所有条件，也不能把所有组合都返回空当作正确结果。
- 通过浏览器依次叠加、替换、移除和清空条件，验证选中态、精确请求和稳定 ID 集合/总数。
  控件相互影响时覆盖两种操作顺序，证明后选条件不会静默丢失先选条件，移除后能恢复原集合。
- 查询语言由 UI 生成时，必须让真实后端 parser/数据库执行生成的请求。期望集合从 fixture
  业务事实独立推导，禁止复用产品的查询拼接函数或用忽略查询条件的 stub 生成 expected。
  拼接字符串单测、请求正确编码、HTTP 200 都不能替代正确命中与排除集合。
- 搜索、筛选、分页的请求证据必须绑定页面实际发出的请求与响应：动作前注册
  `expect_request`/`expect_response`，核对 method、path/query 参数并读取响应集合。测试自行
  重放的独立 GET 只作为权威回读，不能替代“页面发出了正确查询”的证据。
- 列表、total、直方图、统计和导出消费同一过滤条件时，固定资源范围与时间窗口逐一验证。
  声明同一统计口径的结果必须守恒；分页、当前加载行导出等口径差异须明确，不能盲目比较数量。
  有已知命中记录却返回空、生成的组合表达式因语法降级改变过滤语义、旧请求结果覆盖新筛选，均不得记为成功。

日志组合查询回归（ZSTAC-89654）的强制合同：文本与快捷词组按 AND 组合，组内按 OR 组合；
文本＋单快捷词、文本＋多个快捷词、带引号的短语、切换和移除快捷词分别验证。
例如 `WARNING AND (Traceback OR ERROR OR WARNING)` 必须保留已知 WARNING 记录，不能接受
空格拼接后静默返回空。搜索和 histogram 使用相同 node/instance/source/from/to/q，
对比准确命中 ID、total 与桶合计；固定窗口内的数据必须已由真实采集链路收录，不能依赖会过期的历史日志。
这是新增验收要求，不表示该 Jira 已修复或已有浏览器 case；现有日志导出 case 不自动继承此覆盖。

## 时间控件与观测数据

当前 TSDB `QueryRange` 和日志时间搜索包含右端点。
测试以 [TSDB](../../internal/server/tsdb/tsdb.go) 与 [日志查询](../../internal/server/logstore/query.go)
的实际精度与合同为准；其它端点单独声明。以固定 `T0` 的闭区间 `[T0-W,T0]` 为例，至少放置
区间内、左边界、左边界前一精度单位、右边界、右边界后一精度单位、很久以前和未来记录，精确断言集合。
不得为套用规范改产品时间语义；合同变更必须同步 API、组件、文档和边界测试。

- 两类时间组件分别盘点，不能用一次 `time-range` claim 代表全站。每个可见 preset 是独立维度。
  验证 UI 选中态、UTC 请求窗口/step、HTTP 响应、真实样本；聚合的 bucket 边界另测。
- custom 覆盖合法、反向、缺一端、取消、再次编辑、确认，以及产品实际支持的最大窗口。
  没有最大窗口合同就不能发明 `max+1` 错误；有合同必须验证边界且拒绝后不查询。
- `TimeRangePicker` 进入 custom 编辑不应立即请求，确认后才提交；监控 URL/follow 与历史快照
  按各自合同验证，不能把一次请求的滚动时间与固定快照混为一谈。
- retention 提醒与请求非法是不同状态。长范围可以合法但部分数据已过保留期；验证提醒和可用
  数据，不能把返回空样本当查询成功的充分证据。
- 切换节点/GPU/部署/实例/评测点位后旧曲线不得残留；0、无样本、离线、过期与采集失败分别显示。
  受控源产生已知日志/指标，经过真实采集和查询链路验证；直接写库仅证明查询边界。
- 网关时间、引擎排队/预处理/首 token、吞吐与显存须按 [推理指标词表](../../docs/reference/inference-metrics.md)
  的来源和单位验证，不把不同阶段重复相加；估算 token 保留近似标识。

## 表单与 CRUD 合同

每张表单维护字段清单：稳定 field ID、标签/单位、组件类型、必填/默认值、合法范围、条件显隐、
请求字段、持久化字段或非持久化理由、适用运行时效果。服务端字典生成的字段按字典驱动清单，
不能仅测试固定的 vLLM 参数子集。字段文案来自 locale，不用后端内部名代替用户合同。

每种可变资源分别登记 Create、Read、Update、Delete；“生命周期通过”不能代替四项证据。
只读 inventory、系统目录、实例派生状态逐项写明不可操作的原因。

| 操作 | 必测闭环 |
|---|---|
| Create | 最小合法、全部可选值、字段负例无 mutation、服务端拒绝保留草稿、取消/Esc 无 mutation、重复提交、刷新与独立 GET |
| Read | 列表与详情字段一致、深链与重进、不存在/失效/未授权、异步加载和重试 |
| Update | A→B、开→关→开、有值→空、省略与显式清空、绑定 A→B→空、只改一字段不覆盖其他字段、取消、并发与失败原子性 |
| Delete | 取消无 DELETE、确认显示真实影响、普通行与末页最后行、列表/详情/selector 消失、引用阻止或合同允许的清理、重复删除恢复 |

字段负例必须按真实类型覆盖：空/纯空白、最小/最大/越界、trim、中文与符号、数值负数/小数/非数、
URL 协议/host/path/query/尾斜杠、可选值省略。没有长度上限的字段不能虚构限制。
枚举逐项选择并验证精确值与回读；服务端拒绝时显示具体字段/原因，修正后可提交。
条件项隐藏时陈旧值是否省略、恢复时保留还是清空，必须按合同验证；不能默认全部清空。

部署快捷/专家模式共享同一草稿，模式切换、引擎切换、模板锁定/偏离、手工命令都要验证。
`quick_params`、显式取消默认值、容器 overrides 与 server `/engines` 字典保持一致；预览、创建
快照、instance 命令和 agent workload 应按同一启动配置解释，允许端口等分配后字段的明确差异。
禁止测试侧重新拼装另一份命令来当权威答案。

引用删除必须在测试主体先建立真实引用，刷新确认后由 UI 发起删除。对模型文件、镜像系列/版本、
存储挂载、网络绑定、模板等分别验证阻止或允许的处理、错误中的对象、无部分写入与无悬空引用。
父资源删除、子资源删除与 teardown 是不同场景。**仅当产品提供预览/revision/CAS 时**验证
预览后引用变化导致冲突；目前不存在通用删除预览/CAS，不得编造按钮、字段或未来用例。

### 节点接入期间的控制面可用性

容量验证必须区分接入过程与全部在线后的稳定状态。针对 500→1000 节点场景，分别记录稳定 500、
新增 500 的注册/握手/上报、稳定 1000 的阶段边界，从接入前持续读取真实节点、部署和实例列表，
并按实际请求区分分页、筛选等参数。最终在线数正确或较小规模 churn 通过不能代替接入阶段的响应验收。

每个阶段记录请求数量、HTTP 状态、响应读取失败、超时和延迟分布，使用明确的接口预算判定；
非成功响应、超时和读取失败不得丢弃或计为成功样本，启用采样却没有有效样本不得视为通过。
报告包含二进制 SHA、机器规格、接入速率、读取并发和背景负载，避免把不同环境的时间直接作性能对比。
浏览器另证列表可操作、错误反馈和恢复；L2 负载负责规模与接口预算，二者不互相冒充。
具体阈值及已实现用例以相应测试合同为准；上述要求不代表容量或浏览器 CI 门禁已自动启用。

### 部署和资源效果

控制面接受请求只证明期望状态写入。必须等待目标 deployment/instance 的可观察阶段和实际结果，
记录所用节点、镜像 digest、模型位置、引擎、workload 与本次请求的关系。
recording runtime 生成的 `running` 不得登记为容器或推理通过。

dGPU 矩阵按 backend、vendor、runtime、引擎、架构与探针结论声明。显存额度、算力份额、加权 QoS、
时间片和硬隔离是不同能力，不得用相同绿色标签代替。真实 quota 容器/推理和宿主指标才能证明资源效果。
sleep/wake 的稳定容量、加载峰值和唤醒峰值分别验证；容器存在不等于权重可用，`wake` 返回 2xx
不等于可服务。详细语义见 [dGPU](../../docs/how-to/dgpu.md)、[sleep/wake](../../docs/how-to/sleep-wake.md)
与 [部署启动配置](../../docs/explanation/launch-config.md)。

测试网络/模型/镜像同步时证明实际目标可消费字节，不能只验证探针握手成功。失败、取消、断线与
重试覆盖部分文件、runtime load 失败和清理失败；验证原始失败原因保留、资源不泄漏、恢复不重复创建。
具体重试/续传能力按实现声明，不能假设所有来源都支持断点续传。

### Playground 和推理结果

每个已声明 operation 独立登记，不以聊天代替 embedding/rerank/audio/image/video/realtime。
选中的模型、操作、API 合同与实际请求一致；不支持的操作给出明确原因，不能静默改选另一个模型。

- 流式与非流式分别验证消息/增量/结束、错误映射、usage 与取消；上游 fixture 可按唯一 marker
  回查请求。客户端停止后必须观察到上游请求/任务释放，不能只看到按钮恢复。
- 新建、切换或删除本地对话必须断言下一次真实请求的会话边界：body 含本次新消息，且不含旧对话的
  prompt 与 reply。DOM 清空、侧栏数量或渲染文本不能代替请求体证据，否则复用旧历史仍会假绿。
- 多模态上传检查原始字节、MIME、multipart 字段与模型能力；语音/图片/视频检查可解码输出，
  异步视频的查询、完成、失败与删除分别覆盖；链接出现不等于媒体生成成功。
- 对比验证目标模型集合、响应归属、并发限制与部分失败；对话切换/离开页面、刷新、注销的
  生成生命周期依 [页面导览](../../docs/reference/web-ui-tour.md) 验证，不能统一假定导航即取消。
- expert/raw 请求、preset、复制 curl 与 UI 常规表单各验证真实 wire；未知 action/expect 必须报错。
  用例 manifest 里的 `inputs` 必须真实驱动交互，不能仅抄入报告。
- Markdown/HTML/SVG 按不可信内容处理。验证 sandbox 无同源权限、默认网络隔离、设置变化后的
  网络合同、剪贴板和 CSP；恶意内容不能读取控制台会话或驱动管理操作。

### 观测事实与多维统计

请求指标、评测、节点资源和日志各有权威来源；同一实例从节点、GPU、部署或监控卡片展示多次，
不代表多个实例或多次请求。

受控负载使用 runId/marker 和现有请求、部署、实例、评测 point 等标识关联；记录调用前基线、
已知成功/失败/取消请求、权威增量及各视图。完整互斥分组合计应守恒；跨维度不能相加。
重试属于一次业务动作还是多次物理请求，按指标合同区分。counter 重置、缺采样、估算 usage
不能用“数值大于 0”通过；时间窗口/采集间隔造成的误差必须声明可解释的界限。
不存在 canonical ID、去重或精确用量接口时记录 `MISSING_EVIDENCE`，不能虚构幂等键或账本。

## 认证权限与秘密保护

按 [安全模型](../../docs/explanation/security-model.md) 分开验证以下主体，不能把 GPU 节点 token 当用户权限：

| 凭据 | 必测合同 |
|---|---|
| 管理会话 Cookie/绑定会话 JWT | 登录/错误密码/注销、空闲与绝对期限、真实交互 activity、后台轮询不保活、改密撤销、Origin、当前角色权限 |
| 平台 API 令牌 | 所属用户、read/write、过期/撤销、read 对 mutation 拒绝、管理令牌接口本身的限制、MCP 与管理 API |
| 推理服务令牌 | 公开网关模型可见性/调用、无效/撤销、仅展示一次、不能作为管理凭据 |
| 节点与传输凭据 | 节点绑定、过期/重放/错误目标、一次性传输边界；在相应 agent/传输用例验证 |

产品当前有 `admin`/`user` 角色及逐路由管理员限制；非 admin fixture 应走受控用户准备，
不能假定存在用户管理 UI，也不能假定 user 对所有管理 API 都只读。管理员、非管理员、匿名、
平台 read/write、推理凭据分别记录分母。不存在组织管理员、跨租户或 Cloud iframe 权限 lane。
权限既查 UI，也用真实请求验证后端拒绝；菜单隐藏不能代替 403。

GPUWorks 管理前端不维护 refresh token。会话过期按当前实现重新认证并保护草稿；不得编写
不存在的 `/auth/refresh` 成功用例。并发失效请求不能产生多个登录弹窗或无限请求循环。
精确过期使用受控会话 fixture/时钟，不长时间 sleep；改密撤销管理会话不等于撤销平台 API 令牌。

密码、Cookie、Authorization、节点 token、provider key、SSH 私钥、临时下载凭据必须脱敏。
Trace/HAR/截图也可能保存明文；一次性展示凭据的步骤在采集边界就应关闭或遮蔽敏感采集，
产物上传前扫描并阻止泄漏。真实凭据只从环境或 `secrets/` 读取，不进入仓库与公开报告。

脱敏必须在序列化与写盘之前执行，并覆盖 JSON/HTML 转义、URL 编码、异常字符串和 traceback；
不能只替换正常路径的 Python 对象或原始文本。产物扫描针对最终字节及常见解码形式，命中即
阻止上传并使本次运行非 PASS。脱敏与扫描 helper 必须有失败路径自测：在 traceback、响应体或
转义文本中注入合成 secret，断言扫描能拒绝且失败报告不含原文；E2E 用例通过不能代替这项自测。
断言消息、`report.json` 和失败摘要同样不得写入未脱敏的请求头、body 或异常。

处理秘密的 case 默认禁止保存失败截图；确需截图时只能采集明确遮蔽后的安全区域，或在写盘前
对整张图做可验证的遮蔽。秘密值输入、展示、回显检查和重开输入框验证期间必须保持 sensitive
phase，直到所有“不回显/不可再读”断言完成，不能在导入或保存成功后提前解除。失败产物安全
必须有独立回归：在秘密已可见时强制触发回显断言失败，断言最终产物（截图、trace、日志、报告）
中不存在原文；只依赖上传前扫描或“扫描未报警”不能证明截图路径安全。

## 错误恢复与可复制内容

每个主要查询和 mutation 分别登记适用的错误：网络不可达、401/403、资源失效、重复/并发冲突、
字段校验、限流、依赖不可用。使用目标路由实际支持的状态码和 ProductError `code/params`，
按路由分别登记，不能给所有字段错误假定统一状态码。
UI 显示操作、原因和可采取的下一步，按合同保留原输入；重试、取消、修正与重新认证可恢复。
错误后的刷新必须证明没有部分 mutation。request ID 存在时记录；不存在时用 runId、资源 ID、
路径与进程日志关联，不得要求虚构响应头，也不能仅记录“操作失败”。

复制出的安装命令、API 地址、curl、令牌与配置必须验证可使用性：真实点击复制、读取剪贴板、
与展示值和权威配置逐字比较，再在对应网络边界原样执行或交给目标 parser/API 消费。
验证 scheme/host/port/path、无重复 `/v1`、无 SPA HTML fallback，不能先改地址再声称复制正确。
GPUWorks 接入地址由调用方显式提供 `server_url`，不能把监听地址 `0.0.0.0`、runner 回环或旧
`public-url` 假设写入测试。执行命令只允许影响本次隔离节点/目录，执行后验证 agent 或业务响应。
环境不可达记为 `MISSING_EVIDENCE`。复制值含 secret 时不得记录原文。

导出报告读取原始字节，按产品声明格式验证内容、编码、字段、单位、记录数和过滤一致性。
只有合同要求 BOM 的 CSV 才断言 BOM；评测 JSON/HTML 按各自格式校验。

## 定位与等待及真实布局

优先 `get_by_role` + 可访问名称，其次 label/placeholder/可见文本，最后稳定业务 test ID。
先按唯一资源名定位行，再在行内操作；图表或编辑器缺少语义时可以增加稳定 test ID，不能硬编码
Ant Design class、DOM 层级、`:nth-child`、生成 id 或像素坐标。关闭 portal 用真实 visible/ARIA
状态区分；必要时读取触发器 `aria-controls`，不把动态 id 写成固定 expected。

禁止 `wait_for_timeout` / `waitForTimeout` 和固定 sleep 作为同步手段。用 Playwright locator
断言、动作前注册的 `expect_response`/下载/新页事件、fixture 的请求 marker 与有截止时间的条件
等待。JSON 业务结果应轮询权威读接口；循环必须让浏览器事件得到处理，不能阻塞同步 Playwright
事件分发。延迟或并发测试使用可显式释放的 barrier，失败记录最后状态，而不是延长 sleep/retry。
收到 mutation 响应只代表服务端完成；随后的列表、分组、计数和空态断言必须使用可重试的
locator/`expect`（必要时 `expect.poll` 轮询权威读接口），不能在响应到达后一次性读取
`all_inner_texts()`、`textContent()` 或 DOM 快照当作页面已渲染完成。
取消/停止类用例必须用 barrier 让取消发生在请求或流进行中，并从 fixture marker、连接关闭、
服务端日志或资源状态证明上游实际观察到取消；本地按钮恢复或本地 stream 结束不能代替。

每个 P0 流程至少在桌面 1440×900 验证：

- dialog/drawer/详情 region 具有名称，打开后立即位于当前视口；检查 bounding box，不能靠
  locator 点击时自动滚动掩盖不可达。底部操作可达，长表格不能把详情追加到表尾而无位置反馈。
- modal 按 Tab 不进入背景、Esc 按产品合同关闭、关闭后焦点返回原按钮；非 modal drawer 按其
  明确的焦点合同测试，不强加 modal trap。表单 label、错误关联和键盘菜单操作真实可用。
- loading/empty/error/data 四态下页面与弹窗无意外横向溢出、覆盖或误操作；宽表格允许在明确的
  容器内滚动，名称/操作固定列保持可达，不能靠隐藏数据凑通过。工具栏、表格/图表与弹窗间距
  来自共享样式。截图辅助判读，关键布局用几何/计算样式形成可判定断言。
- token→主题/共享组件→页面的适用样式继承不被旁路；真实 Tab、hover、选择触发状态后比较
  computed color/border/outline/spacing 等。expected 来自 token 和组件合同；颜色归一化比较
  RGBA 等语义，不锁死浏览器颜色序列化，也不能退化为只检查 class。
- 中文与英文分别覆盖外壳及核心业务流程。错误插值、单位、帮助、菜单、drawer 与枚举不残留
  错误语言；模型名、用户输入、原始引擎日志不按静态 UI 文案判错。
- 无未处理 pageerror；console error 与关键 API 意外 4xx/5xx 必须归属并判定。负例预期错误
  逐项显式匹配，不能全局忽略 console、网络错误或 401。未归属的 pageerror、console error 或
  意外 4xx/5xx 必须让该 case 非 PASS；只追加到报告或只打印警告不构成判定。

移动端作为独立可选 lane；已有部署移动端检查保留其结果，不计入桌面覆盖分子。桌面门禁不因此
要求新增全站移动验收，也不能用移动截图代替桌面业务与焦点证据。

## 用例组织与覆盖登记

当前浏览器资产使用 Python Playwright，位于 `test/e2e/*.py`；不要求为规范迁移到 TypeScript
或引入新依赖。新增测试按页面/业务组织，登录、数据准备/清理和重复控件操作可复用，关键业务
断言保留在 case。每个入口文件头引用本规范，每个独立 case 前紧邻具体 `Mainline` 注释，例如：

```python
# E2E standard: test/e2e/browser-e2e-testing-standard.md
# Contract: gpuworks/deployment/create-explicit-source
# Mainline: 创建自有模型与候选 → UI 选定 peer 来源并部署 → 刷新核对来源快照
#           → 目标节点取得相同文件并启动容器 → 经真实网关请求成功 → 删除并核对清理
```

一条 case 验证一个完整闭环，名称使用“页面 / 场景 / 结果”。串行脚本必须逐 case 输出结果，
前一个失败导致后续未执行时记 `NOT_RUN`，不能把整个脚本的一个通过数当所有场景通过。
需要共同前置的用例仍必须独立准备数据、单独可运行，并支持声明范围内的并行。

### 说明归属与去重

| 内容 | 唯一维护位置 |
|---|---|
| 验证什么、预期结果和证据链 | case 名称、紧邻 case 的 Mainline、步骤注释与实际断言 |
| 运行命令、参数选择、专用 fixture/环境前提 | 可执行入口文件头的 docstring；CLI 参数以实际 parser 为准 |
| 字段合同、CRUD/组件维度、case 绑定及未覆盖项 | 对应 `coverage/*.json`；引用真实文件/函数/参数，不复制完整操作正文 |
| 本次是否通过、SHA、runId、证据与清理结果 | 本次执行报告；源码中的清单和注释不保存历史通过数 |
| 通用依赖、执行方式、保密及产物管理 | `README.md` |
| 环境能力与后续候选维度 | `single-machine-coverage.md`；不维护第二套已有用例清单或运行结果 |

新增或修改 case 时，默认只更新用例及其覆盖清单；只有通用运行约定改变才修改 README。
新增 Make target 定义放在功能独立的 `test/e2e/*.mk`，由根 Makefile 统一加载；不要在同一共享
位置反复插入 target。是否加入 `test-e2e-local` 是独立选择合同，不因增加 `.mk` 自动扩展套件；
迁移入口时须比较展开后的命令、构建依赖及选择集合，保持原行为。
不得另建逐用例 Markdown 来承接从 README 删除的重复业务描述。参数化 case 必须分别写出各参数
的 Mainline，步骤注释应紧邻相应断言；共用准备/清理可以复用，但不能用统一“生命周期”注释
掩盖不同分支。缺口仍保留在清单，不能通过去重删除 required evidence、降低覆盖分母或补写未执行的 claim。

整理已有 case 时先核对断言，已有明确 Mainline/步骤的不重复扩写；注释只解释实际测试内容。
仅调整文档、注释或帮助文字时，用原有测试和执行逻辑等价检查确认行为未变，无需为文案增加镜像测试。
MR 评审应确认共享 README/盘点表没有逐功能追加段落，清单能够回指 case，报告绑定本次实际执行的提交。

维护唯一的机器可读覆盖清单，字段至少如下；这是清单的合同，**不是已经存在的 Registry 工具**。

| 字段 | 要求 |
|---|---|
| contract/page/control/field ID | 稳定、唯一，改名不自动退役；资源 CRUD 分项；枚举每项、时间每个 preset 独立维度 |
| 业务合同与优先级 | 产品/API/组件来源、P0/P1、主线名称、已发布或本次交付的行为 |
| 环境与主体 | 浏览器、runtime/vendor/拓扑、身份、依赖与 fixture；本地/容器/L4 分别声明 |
| required evidence | 适用的 UI、request、persistence、execution、runtime、cleanup；只读或本地存储例外写理由 |
| 执行绑定 | 真实文件、case ID、可执行命令、源码与构建 SHA、runId、状态及证据路径 |
| 不适用与退役 | `N/A` 的产品理由、审阅记录；retired ID 与替代合同保留，不复用 ID |

清单 item 编号只能绑定语义相同的断言。绑定须同时可回查清单原文与 case 中的断言位置；不得为了
消除缺口把别的断言塞进空缺编号，也不得改写 item 原意后继续复用编号。原 item 未被本 case
覆盖时保留 `MISSING`/`N/A` 及理由，不能把未覆盖项伪装成已绑定。

语义绑定按断言而不按控件存在判定：

- 删除/轮换确认的 item 要求“名称及影响”时，必须断言确认标题或描述中的真实对象名称和影响
  文案；只断言 Popconfirm 可见并点击主按钮不算覆盖，应缩成 `MISSING` 或补断言。
- `5.x`/选择器搜索 item 只有真实输入搜索词、核对候选过滤与空结果才可绑定；用标签键选择、
  chip 清除或普通下拉选项不能代替搜索。
- “真实冲突”item 必须构造服务端冲突（重复名称、被引用、唯一键等）；客户端格式/非法输入拒绝
  是另一条负例，不能顶替冲突语义。
- 允许/阻止、引用保护、清理等 item 需要对应成功与拒绝两侧的实际断言，另一侧未执行时保留缺口。

组件清单是**写前设计输入**，不是事后勾表。每个 case 在写断言前先完成：

1. **逐页盘点**：列出实际可达的组件实例、字段、选项、条件控件、状态和请求语义；相似文案或同一
   组件类型不能合并。
2. **适用项映射**：从清单选出本 case 适用的编号，逐项写出“该编号要求的具体断言”；不适用写
   `N/A + 产品原因`，适用但本次不做写 `MISSING`。不能用一个段落吞掉整节（例如只写“键盘/焦点未覆盖”）。
3. **绑定可反查断言**：manifest 的每个绑定项要能指向 case 中的步骤、字段、单元格或请求体；只凭
   标题相似绑定属于假绑定，按未覆盖处理。
4. **通用项不能当填充**：`1.14` 持久化、`12.7` 确认、`13.5` 通知、`17.1` 指标等跨页面通用项，
   只有满足其完整语义（独立回读、名称+影响、数值+单位等）才能绑定；绑定数量不等于组件质量。
5. **正反两面**：组件清单同时约束正向主线和负例矩阵；每个适用组件的校验、禁用、错误、键盘/焦点、
   空/失败态逐项登记，不能只写主路径。

真实 review 的反例：只点 Popconfirm 就绑 `12.7`；只在 API 看数字、UI 只查 verdict 就绑 `17.1`；
只刷新看到标题、没有独立回读就绑 `1.14`；用 chip 选择代替搜索却绑 `5.x`；把整个键盘/焦点章节写成
一句 `MISSING`。这些都应逐项补断言或降级为 `MISSING`。

状态分别记录 `PASS`、`FAIL_PRODUCT`、`FAIL_TEST`、`BLOCKED_INFRA`、`BLOCKED_PRODUCT`、
`MISSING`、`MISSING_EVIDENCE`、`NOT_RUN`、`N/A`、`RETIRED`。仅声明场景而未完成断言不允许 PASS。
每个 evidence claim 在断言成功后产生，能回查响应/日志/资源与本次 runId；缺 required evidence
不得登记业务主线 COMPLETE。
尚未交付的规划能力不自动进入“已有能力”清单；纳入本次交付范围的产品缺陷继续作为 blocker
计入该范围，不能标 N/A。退役需要产品依据、影响审阅和保留 tombstone，禁止删除清单来提高覆盖率。

每个 lane 的分母在运行前固定为其全部适用 active 合同和 required dimensions；失败、缺用例、
未运行及阻塞均不能从覆盖分母删除。分别报告执行通过率与覆盖完成度，并列出分母和缺口。
只允许有产品理由的 N/A 排除，环境没有 GPU 是 L4 阻塞，不是该功能 N/A。
组件行覆盖率、路由触达、脚本数和计划数量均不得冒充业务覆盖率。

## 执行入口与门禁

现有入口如下，执行前核实依赖；它们的名称不代表浏览器业务已经满足本规范：

```bash
make build                            # 含 UI、字典/i18n、类型检查、server 与 agent
make test-ui                          # node:test + RTL/jsdom，不是真实浏览器
```

| 阶段 | 必跑范围 | 阻断规则 |
|---|---|---|
| PR | 受影响共享组件合同、页面 P0 闭环、字段负例、筛选负例、持久化与适用运行时；改共享组件追踪消费页面 | 缺证据或失败阻止该变更验收；硬件能力单列所需 L4 证据 |
| 主线 | 全部本地 P0、认证/令牌、容器 fake-engine 数据面闭环及资源清理 | 阻止发布，不能只依靠 RTL 绿灯 |
| nightly/显式 L4 | P1 与全列表/字段/错误/并发矩阵、声明的 runtime/vendor/拓扑和外部兼容 | 必需 lane 阻塞即验收未完成；按范围修复，禁止静默重试 |

默认 retries 为 0；flake 修同步或隔离。定向运行只能形成定向报告，不能覆盖完整权威报告。
接入自动门禁时必须固定 selection contract 和 Registry 内容指纹，校验 SHA 与构建、实际可达
页面/控件、case 绑定与 evidence 完整性；未知 action/expect/claim、未注册控件、only/skip/fixme、
降低阈值、删除目标维持 100% 均应失败。产品选项变化必须显式更新合同，不允许测试自动自减分母。
按 lane 分别核验全部目标、组件维度、业务主线、runtime、P0、P1 的适用集合，权威全量验收需
精确 100% 完成；尚未实现的清单/门禁本身标为基础设施缺口，不能宣称全量达标。

失败产物至少包括 runId、case/contract ID、SHA、环境、trace/截图、脱敏请求摘要、原始失败、
server/agent/runtime/fixture 关联日志与清理结果。源码与合同提交评审，临时数据库/密钥/缓存不提交；
可公开验收记录按 [文档落位规则](../../docs/README.md) 存放，CI 产物按项目保留策略保存。

## 变更验证与提交门禁

浏览器 case、共享 fixture/helper 或覆盖清单变更在提交前，除了本次定向运行，还必须完成以下检查；
缺一项即视为证据不完整，不能用“旧基线通过”或单次定向输出代替。

- **目标分支兼容**：先 fetch 目标分支，把本次变更 rebase/合入目标当前 tip，在合并结果上重新构建
  并运行受影响的 en/zh case。报告记录目标分支名与 SHA、合并后 HEAD、实际命令和每个 case 结果；
  评审期间目标分支前进时重新合并并重跑。不能只在分支起点、旧 worktree 或 cherry-pick 前的树上
  取得 PASS 后提交，也不能为了避开目标分支变化而选择旧基线。
- **断言敏感性**：每个新增/修改 case 至少做一次变异检查：移除或破坏其核心行为（UI 入口、请求
  参数、落库/调和、运行时效果或 fixture 的关键分支），确认 case 在拥有该行为的断言处失败。
  记录变异点、期望失败和实际输出；变异后仍然通过说明 case 没有证明行为，必须修正后重跑。
  只删断言、放宽 expected、改成 existence-only 或只留 smoke 不算通过。共享 fixture/helper 的
  改动同样要有失败路径自测（secret 泄漏、清理失败、非预期或半截响应、取消未生效），E2E 绿灯
  不能代替 harness 自测。
- **失败诊断**：失败报告必须给出失败步骤、期望/实际、method/path/status、runId 与相关资源 ID、
  最后一个已完成步骤，足以区分 `FAIL_PRODUCT`、`FAIL_TEST` 与 `BLOCKED_INFRA`。只有 traceback、
  截图或“操作失败”不构成诊断；失败现场与清理结果按上节保留并脱敏。
- **PASS 聚合**：PASS 只能由“业务函数正常返回且此前没有异常”推出，并同时要求清理成功和
  浏览器/context 实际关闭成功。`finally` 或收尾函数不得凭 `case_completed`、目录存在或 evidence
  已写入把已记录的 FAIL 改回 PASS；`context.close`/`browser.close`/server 或 fixture 停止抛错
  必须保留为 FAIL 并写入报告。共享入口须有失败路径自测：注入一次关闭异常，断言运行非 0 且
  报告不是 PASS。
- **共享产物字节保真**：trace、HAR、截图和附件等共享资源写入时必须保留原始字节；只能对确认是
  文本的资源做解码/脱敏/再编码，非 UTF-8 或二进制资源（PNG、字体等）逐字节复制并单独扫描。
  禁止用 latin-1 解码后按 UTF-8 重写改变字节。共享 helper 须有真实二进制资源的逐字节自测。
- **提交报告**：MR 写明目标分支与 merge-base、变更 SHA、实际执行的 locale/case/命令、每个 case
  的 PASS/FAIL/NOT_RUN、敏感性检查、清理结果和已知缺口。只贴一次成功输出、只跑单一 locale
  或报告 SHA 与提交不一致，都不能声明该变更按规范完成。提交者先按本规范自审，再由未参与该
  用例编写的评审者按同一清单复核；自审和“脚本能跑”不能代替独立评审。

## 发行包与跨进程组合验收

安装、升级、agent 分发与代理入口的验收必须从最终边界执行，组件测试和源码断言不能单独关闭
交付合同。按 [发布与内嵌资产](../../docs/dev/release.md) 记录发行包、server、各架构 agent、内嵌资产与目录包
的内容摘要和版本，不用文件名代替内容身份。声称支持的架构分别验证，不用交叉编译成功代替启动。

- 全新安装从空 data 目录和最终发行包开始，验证迁移、首次凭据、内嵌 HTML/JS/CSS 的内容与 MIME、
  浏览器登录、从该 server 分发的 agent 接入，再走适用的部署与真实推理闭环。
- 升级使用带模型/部署/设置/凭据的旧版本数据，验证用户草稿之外的持久化、重新登录合同、
  server/agent 版本兼容和现有实例服务；升级失败的回滚必须验证配置、密钥与数据一致性。
- 重复安装、重启、卸载与重装验证本次服务进程、目录、端口与资源的实际结果。产品明确保留的
  数据不得当泄漏删除，安装测试也不能操作其它 worktree 或在线 agent 的数据。
- 经反代访问时，从用户实际入口加载资源、生成接入/推理地址并执行，不用内部直连代替。
  server 健康、agent 在线和网关业务响应分别判定，任一缺失不能称完整系统健康。

每条组合合同绑定可执行入口和本次 artifact；尚无 fixture 或无法执行时标明缺证据。

## 完成定义

新增或修改一个控制台能力，只有满足以下条件才可宣称其适用 E2E 闭环完成：

- 术语、组件、字段、枚举、列表、时间与权限合同已盘点，产品漂移已解决或明确阻塞。
- 实际可达控件与相互影响路径逐项登记，关键组合的命中/排除和跨视图语义有真实证据；子集通过未扩称整页覆盖。
- 适用 CRUD、边界、负例、取消、并发、失败恢复和引用保护均有独立证据。
- UI 发起的操作经精确请求、刷新/重进与权威回读证明；异步工作到达真实执行结果。
- 影响容器、文件、网络、鉴权、推理或显存的变更具备对应运行时证据，替身范围未被夸大。
- 页面组合的键盘、焦点、视口、计算样式、两种语言与敏感信息处理已验证；处理秘密的流程在失败时
  也不会产出含明文的截图、trace、日志或报告。
- 记录所有适用维度及未通过原因；没有把声明、截图、toast、RTL 覆盖率或 teardown 当业务完成。
- teardown、browser/context 关闭或 fixture 停止的异常会保留为失败，不被 finally 聚合成 PASS；
  共享 trace/资源写入保持原始字节。
- 用例独立可重放，无固定 sleep/静默 retry；执行命令、依赖、产物和 scoped cleanup 可复查。
- 已在当前目标分支的合并结果上重建并重跑适用 locale；核心断言通过变异检查，清理为实际观察到的
  成功，报告绑定本次提交与 runId。
- 适用门禁全部满足；尚未实现或未执行的门禁明确列为缺口，不以编写本规范本身宣布完成。
