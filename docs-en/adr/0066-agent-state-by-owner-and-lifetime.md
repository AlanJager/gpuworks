# ADR 0066: Agent state is grouped by owner and lifetime, and the composition root only wires

Date: 2026-11-15 · Status: Accepted

## Context

`internal/agent/app` is one package of 89 files and 15.2k lines (non-test); `NodeRuntime` has 77 fields (counting those inside anonymous structs), 12 mutexes and 233 methods, and `OnRPC`, with the helper switch it hands over to, dispatches 51 RPCs. Images, model files, card health and doctor all hang off this struct and share its locks: a change to any feature changes it, and no subsystem can be tested or replaced on its own.

`internal/agent/engine` keeps an instance's state in 12 parallel maps keyed by UUID, and each exit path deletes some of them. The four that describe the engine process (sleep level, prewarm, L1 host buffer, processes on its cards) are cleared only when the container exits by itself: not when the server removes or stops the instance, and not when a dead container is replaced directly by the next sync. Measured (GWKS-321): a new container under the same UUID was reported holding the old process's L1 host buffer, so the server skipped its host memory check; the new process was not prewarmed; and when an instance desired asleep got a new process, the agent took the old process's sleep for the new one, so the new engine stayed awake with all its memory while the server believed it asleep.

The server's controller was already reorganized this way: one self-locking type per kind of memory (GWKS-304), a test that makes every field say whether it is dropped per deployment, and another that really writes, forgets and asserts nothing is left (GWKS-303). This ADR makes that the agent's pattern.

## Decision

1. **Group by owner and lifetime.** State under one key (an instance UUID, a model file, an image reference, …) that ends at one moment goes into one record (a `struct`), held by one `map[key]*record`, instead of a parallel map per fact. An instance's state is split into records by lifetime: the desired generation, one reconcile attempt (in-flight, pending, cancel), and one engine process (`processFacts`).
2. **A record is bounded by what it describes.** The engine process's record starts empty where a container is created and is dropped whole where the container is confirmed gone (`reclaimInstance`) and on a runtime switch, never piecemeal on each exit path. The empty start covers every replacement that does not pass through `reclaimInstance` (a dead container replaced directly by a sync, a runtime switch). A new fact goes into the record it belongs to and is cleared with it. Code that writes the record runs inside that UUID's reconcile attempt (the inFlight serialization); a removal drops it only after the attempt ends, so no old attempt writes it back.
3. **Every field is classified, and per-instance cleanup is proven by a test.** `TestEveryEngineFieldIsClassified` lists each `Engine` field: per-instance ones say whether the server removing the instance drops them; the others say whether they are a dependency, configuration, a lock or a global counter; a map keyed by string can only be per-instance. `TestRemovingAnInstanceLeavesNothingUnderItsUUID` makes a sleeping instance leave entries in every table, removes it, and asserts no field marked as dropped still holds it. This is the same pattern as the controller's `TestEveryControllerFieldIsClassified` with `TestForgetDeploymentLeavesNoMemory`. A new field fails until it is classified, or until it is cleared if marked as dropped.
4. **Subsystems own their state and locks, behind narrow dependencies.** Images, model files, card health and doctor each become a package or type holding their own fields and locks, given only the interfaces they need (driver, reporter, storage guard, …), testable from a zero value or a constructor. `NodeRuntime` is the composition root: one field per subsystem, plus the connection and lifecycle wiring.
5. **Shared state belongs to the composition root, and locks do not cross subsystems.** Configuration several subsystems read and services they share (the network configuration `netcfg`, the models directory, registry auth, the puller, and `registries`, which remembers the registries that just failed) are held by the composition root and handed to subsystems as a read-only getter or snapshot; no subsystem holds another's configuration lock. Subsystems do not take each other's locks: to look up another subsystem's table (the peer relay looks up both model syncs and image syncs) a subsystem calls a narrow method the other exposes, which answers under its own lock. No code holds two subsystems' locks at once.
6. **RPC is a table, not a switch.** `OnRPC` becomes a "method name → handler" table whose handlers the subsystems provide; `NodeRuntime` only looks them up and handles the shared errors.
7. **A ratchet keeps it so.** `agent_node_runtime_fields`, `agent_node_runtime_mutexes`, `agent_node_runtime_methods`, `agent_onrpc_cases` and `agent_engine_struct_maps` in `scripts/arch-constraints.txt` only go down (initially 77 / 12 / 233 / 51 / 9); loosening one needs a `# raised:` reason. They are measured by `scripts/structcount` on the syntax tree: several names on one line count per name; pointer locks, `sync.Map` and map types of the package count; fields inside an anonymous struct still count (wrapping is not leaving); RPCs `OnRPC` hands to a helper switch count, and so do RPCs compared with `==` or written as keys of a table of handlers or closures; a function that takes the type as a parameter, whatever it is a method of, counts as a method of the type. Only moving into a named subsystem type counts as leaving. The method count guards behaviour: fields moved away while their methods stay on `NodeRuntime` and touch the subsystem's state directly is not a split.
8. **Classification: the entry decides the owner, the writer decides the state.** Business logic enters the agent in four ways: an RPC, a field of the state sync (`proto.DesiredState` / `proto.StateUpdate`), a stream, or a call from the connection or the process entry to an exported `NodeRuntime` method (the facts a status report asks for, other envelopes, startup). Every entry has exactly one owner; the owners and each entry's owner are recorded only in `internal/agent/app/owners_test.go`. New business logic is classified in this order:
   1. **An existing entry**: the logic is written in the owner the table gives that entry.
   2. **A new entry**: its owner is the owner of the state the request writes; for a request that only reads, the owner of the state read. When it writes two owners' state, it belongs to the owner of the lock that serialises the operation, and the other is called through a method it exposes. An entry that carries another entry (the peer relay) hands the payload unparsed to the payload's owner. Once decided, a line is added to the table; when the owner has a handler table of its own, the RPC is added to that table.
   3. **State belongs to the owner that writes it**, together with its lock, in the owner's own type. Another owner that needs to read it or invalidate it calls its method; the side that triggers gets that method as a function dependency (as `engine.WithLogDrain` does) and does not take its lock.
   4. **What several owners share**: the only synced configuration and shared services are those listed in decision 5, held by the composition root, and adding to the list means changing this ADR; code that remembers nothing goes in a leaf package under `internal/agent/` that does not depend on `app`.
   5. **A background loop** belongs to the owner of the state it writes; one that only reports belongs to the owner of the state reported. One loop serves one owner.

   An owner with a type of its own is held to a stricter standard: it takes one field of `NodeRuntime`, that field appears only in its accessor function, and all of its RPCs are handled by its own table. The state of the other owners is recorded field by field in `fieldOwners` for now. The tests that enforce this: `TestEveryRPCHasOneOwner`, `TestEveryStreamHasAnOwner`, `TestEverySyncedFieldHasAnOwner`, `TestEveryExportedNodeRuntimeMethodHasAnOwner`, `TestEveryNodeRuntimeFieldHasAnOwner`, `TestAnExtractedOwnerIsReachedOnlyThroughItsAccessor`, `TestNoTypeHoldsTheNode`, `TestNoLockIsPassedAround`.

## Consequences

- First step (GWKS-321): the engine process's four maps become `processes map[string]*processFacts`, starting empty when a container is created and dropped whole in `reclaimInstance` and on a runtime switch; `Engine` map fields go 12 → 9. A new container under the same UUID no longer inherits the old process's facts: `TestANewContainerUnderTheSameUUIDKnowsNothingOfTheOldProcess` (the server removing or stopping it) and `TestAReplacedEngineProcessIsPutToSleepAgain` (a dead container replaced by a sync, a runtime switch: the new process really is put to sleep again).
- Second step (GWKS-503): images become the first owner with a type of its own, `nodeImages` (`internal/agent/app/images.go`), which holds the catalog inventory, the image operation slot, the cancellable operations and the peer transfer tables, together with their three locks; what it needs is given by the functions of `imageDeps`. The numbers are in `scripts/arch-constraints.md`.
- The remaining owners are then extracted one at a time: model files → card health and doctor → the rest, each merged on its own, tightening the ratchet as it goes. When all are extracted `rpcOwners` is empty and is deleted.

## Costs and what is not done

- `runtimeEpoch` is kept per UUID for the agent process's life on purpose: a removal moves it to a fresh global value, so a reused UUID never matches an old attempt. The cost is one `uint64` per UUID seen.
- The desired-generation and reconcile-attempt maps (`desired`, `inFlight`, `inFlightCancel`, `pending`, `cleanupRequired`) are not merged in this step: they are maintained together by reconcile's serialization protocol, and merging them means changing that protocol with them, which is a change of its own.
- The judgement in rule 2 (whose state is written), the leaf package of rule 4 and the background loops of rule 5 have no test and rest on review; the tests only ensure that every entry and field has a line saying whose it is, and that an extracted owner is not bypassed. What the tests do not see: one owner's state placed inside another owner's type; a new field or a new exported method labelled wiring or shared (review checks it against the list in decision 5).
- `nodeImages` staying in package `app`, and being wired to `NodeRuntime` on first use, are both transitional: most tests build a `&NodeRuntime{}` literal, and the package still holds functions several owners share. Once the literals use a constructor it is wired at construction; once model files are extracted and the shared functions are in leaf packages, the two become packages of their own.
- Streams are still passed on by one `NodeRuntime` method per kind on `conn.Handlers`, with no "kind → handler" table; a new kind of stream costs one method against the ratchet.
- Splitting subsystems does not change the agent–server protocol or behaviour.
